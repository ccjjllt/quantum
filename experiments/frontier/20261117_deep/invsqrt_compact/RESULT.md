# invsqrt `0af21cb8`：wire 压实（重命名/复用）能否到 42Q / 40Q？

日期 2026-11-17。分支 `main`（只做静态分析，见 §7 关于「本地 vs Kaggle 官方」的区分）。

**判定：INFEASIBLE（不可行，缺 2 条并发工作位）。**
同门序列的**并发活跃峰值 = 44**（模型无关，三套口径同值；峰值 op 1689 = `CCX q16 q17 q43`），
`0` 对 wire 的生命期不相交，区间图色数 = 44。所以「只改 wire 编号、门 multiset 不变」
的压实到 43/42/40 在数学上不存在——不是没找到，是不存在。要 42Q 必须**消掉 2 个活跃值**
（重算），最便宜一对 ≥ **132 C**，而 42Q 的盈亏平衡余量只有 **80.95 C**（1.63×）；
若目标是金线，42Q 连零成本都不到线（见 §6）。

## 1. 假设

前人的 110/110 失败是**删 wire**（把一条线的角色整体拿掉）。压实是另一件事：
两条物理线若生命期不相交，可以把它们映射到同一个声明编号上，门表一字不改。
成本 `Q·(Toffoli + T/4)` 对 Q 线性，所以 44→42 是白拿 −4.55%，
44→40 是 −9.09%。本实验检验：**这条门序列的最小并发宽度到底是多少。**

## 2. 方法（三套口径，互为交叉检验）

从 `invsqrt_0af21cb8.kmb.b64` 还原 180,382 B（base64 → zlib → `.kmb`，
sha256 `0af21cb8…6b1b`），用 `kickmix.Circuit.from_file` 读入并导出 `.kmx` 文本
（`experiments/frontier/20261117_deep/invsqrt_compact/invsqrt_0af21cb8.kmx`，sha `afc08f07…b5931`）。
解析出 **20,833 条 op**（其中 1,394 条是 `PUSH/POP_CONDITION`，实际带 wire 的 op 19,439 条；
op 编号沿用前人 body 索引，`CCX q16 q17 q43` = op 1689，与 `invsqrt/RESULT.md` §C 一致）。

| 模型 | 定义 | 为什么需要 |
|---|---|---|
| **A** | 朴素区间 `[首次触及 op, 末次触及 op]` | 任务书要求的口径；最保守 |
| **B** | **常量性**：wire 只要持有「不是已知计算基常数」的值就算占用 | 真正的物理判据。本件所有写都是**异或累加**，旧值被下一次写消耗，所以释放点**只能**是无条件 `HMR`（measure+reset，复位到 \|0>） |
| **C** | **复位分段**：把每条线在无条件 HMR 处切成段，再对段做区间图着色 | 允许「测量后复用」；色数 = 这条门序列的最小物理线数 |

B 的细节：起点 22 条 x 线（q0–q21）置为「非常量」（输入是任意 \|x>），scratch 置为
\|0>；`X` 在常量上翻转值、非常量保持；`CX/CCX` 按控制位传播；`CZ/CCZ/Z/Z_POW/R`
只动相位；`SWAP/CSWAP` 交换；`HMR` 复位。**没有任何条件 HMR**
（`conditional HMR 0/1276`），所以「条件块的复位不可信」这条顾虑不存在。

## 3. 实测（本机静态 + Kaggle CPU 上用**官方 kickmix.so** 复算，两次完全一致）

| 量 | 值 |
|---|---|
| **A 区间峰值** | **44 @ op 1689** |
| **B 常量性峰值** | **44 @ op 1689**（`CCX q16 q17 q43`），此时 **44/44 条线全部非常量** |
| **C 复位分段峰值** | **44 @ op 1689**；段数 1,308（q41 255 段、q42 333 段，说明 HMR 复用已经用满） |
| **C 贪心区间着色（= 该门序列的最小物理线数）** | **44** |
| **生命期不相交的 wire 对** | **0**（`C(44,2)=946` 对全查） |
| 占用 = 44 的 op 数 | **4,195**（op 1689–18157，占 20.1%） |
| 占用 ≥ 43 / ≥ 42 / ≥ 41 / ≥ 40 的 op 数 | 8,642 / 11,270 / 12,863 / 14,534 |
| 占用分布 | 44×4195, 43×4447, 42×2628, 41×1593, 40×1671, 39×1152, 38×332, 37×281, 36×215, 35×189, 34×211, 33×221, 32×416, 31×291, 30×268, 29×432, 28×436, 27×210, 26×166, 25×28, 24×45, 23×9, 22×3 |
| 拿掉任意**单条**线后的峰值 | 44 → **43**（44 条线逐条测过，全部 43） |
| 拿掉 **2 条** A 组线（q24+q25 / q22+q25 / q22+q23） | 42 |
| 拿掉 **4 条** A 组线（q22–q25） | 40 |

**峰值的结构**：op 1639–1689 这 50 条 op 是「新 AND 目标连续落地」的爆发段
（q41@1639、q42@1663、q43@1689 三条全新 scratch 线在 50 条 op 内被 `CCX q16 q17 …`
创建），而此刻 22 条 x 线（q0–q21）与 q22–q40 全部还在承载数据。逐线看
`lastHMR<1689`：q0–q25 全为 `None`（峰值前一次都没被复位；x 线最早的 HMR 是 q19 的
op 2931，q22–q25 唯一的 HMR 落在收尾 op 20734–20776），其中 **q0/q1/q2/q3/q4/q5/q6/
q12/q14/q15 十条 x 线全程从未被 HMR**（首末 op 覆盖 1→20,781，整条 tape 是 0→20,832，
几乎全程在线）；
q26–q37 在 1190–1367 被复位后又被 `CX` 重新装入新值；q38/q39/q40/q41/q42 分别在
1180/1594/1621/1639/1663 才第一次被使用。所以 44 不是解析假象：
**22 条输入线 + 22 条 scratch 同时全部有活值**。

## 4. 为什么重命名不可能（论证，不只是搜索）

设门 multiset 不变，只改编号，映射 f: 44 条线 → ≤42 个槽。由鸽笼，f 至少合并 2 对线。
取被合并的一对 (a,b)：在 op 1689 两者都持有非常量值，且该值**都会被下一次写消耗**
（本件所有写都是异或累加，见 §2-B）。合并后该物理槽必须同时向 a 的后续 op 出示 a 的值、
向 b 的后续 op 出示 b 的值；两者演化不同，矛盾。所以「同门 multiset 的压实」不存在。

另外两条常见逃生口也已排掉：

* **编号空间有洞**？没有。44 条线全部出现在门里（`num_qubits = max index+1`，
  寄存器 22 条 x 线也在计数内，实测 `X q5` → Q=6、`APPEND_TO_REGISTER q9` → Q=10）。
* **靠门交换重排降低峰值**？峰值处 44 个值全是「已定义、待读取」的活值，
  换序只能改读写顺序，不能把 2 个值从割上抹掉。
* **把某条线换成经典 bit（条件门）**？这会**改变门表**（新增 `if b` 条件门），
  超出「同门 multiset」的约束；而且峰值处 44 条线全部持有非恒定量子值，
  连一个可替换对象都没有（可替换的只有 HMR 之后 \|0> 的线，已计入「空闲」）。

## 5. 要 42Q / 40Q 必须付什么

唯一方向是**消掉活跃值**（退役 + 就地重算），不是复制 wire（复制是反方向）。
按线退役的精确下界已由前人的 atom/GF(2) 定价给出（`invsqrt/RESULT.md` §C′）：
q25 ≥ 77 Toffoli、q24 55、q23 161、q22 1077（= C 单位，因为 1 Toffoli = 1 C）。

| 目标 | 需消掉的活值 | 最便宜组合 | 价格 | 盈亏平衡余量 | 倍数 |
|---|---:|---|---:|---:|---:|
| 42Q | 2 | q24 55 + q25 ≥77 | **≥132 C** | +80.95 C | **1.63×** |
| 41Q | 3 | + q23 161 | **≥293 C** | +124.39 C | **2.36×** |
| 40Q | 4 | + q22 1077 | **≥1,370 C** | +169.99 C | **8.06×** |

（任务书写的「42Q 余量 81.12 C」是按 C≈1,700.06 四舍五入；按官方 cost/44 =
**1,699.940122** 算是 **80.95 C**。差 0.17 C 不影响任何判定。）

而且 q25 那条（全场最便宜）**已经被造出来并用官方 verifier 判 FAIL**
（`x was not restored`，kernel `jiyujia/qcc-invsqrt-q43-retire-q25` v2），
所以 77 是乐观下界、真实价更高。结论：**宽度这条路在本件上没有任何价格可行的入口。**

## 6. 对任务书目标数字的一处更正（会改变结论的读法）

任务书与 `docs/ceiling-20261117.md` §2.1 写「42Q 的 C 预算 = 1,781.06（+4.78%）」。
1,781.06 = `1699.9401 × 44/42`，这是**分数不变**（GM 仍 28.1509）的盈亏平衡点，
**不是金线门槛**。金线要求 `Q·C ≤ 70,486.58`：

| Q | 金线所需 C | 相对当前 1699.9401 | 同门表只压宽度后的 GM | vs 金线 28.71339 |
|---:|---:|---:|---:|---|
| 44 | 1,601.97 | −97.97 | 28.1509 | −0.562 |
| 43 | 1,639.22 | −60.72 | 28.3675 | −0.346 |
| 42 | 1,678.25 | **−21.69** | **28.5909** | **−0.123（不到线）** |
| 41 | 1,719.19 | +19.25 | 28.8214 | **+0.108（过线）** |
| 40 | 1,762.17 | +62.22 | 29.0596 | +0.346 |

即：**即使 42Q 压实完全成功且 C 一分不涨，GM 也只有 28.5909，仍差金线 0.123**；
纯宽度路线要过金线得做到 **41Q**（40Q 更稳）。这把 §5 的价格表进一步收紧：
41Q 需要消 3 个活值 ≥293 C，而金线在 41Q 只给 +19.25 C（15×）。

## 9. 结论与下一步

1. **压实关闭**：峰值 44、0 对可合并、区间色数 44。42Q/40Q 不是「没试过」，是**不存在**。
2. 宽度轴真正需要的不是「减线」而是**新合成体**：在 op 1639–1689 那段爆发里，
   scratch 并发 ≤ **20**（当前 22），且 x 侧 22 条已全程连续活跃、无压缩余地。
3. 若仍要走宽度：42Q 需 ≥132 C（1.63× 余量），41Q 需 ≥293 C（金线只给 +19.25 C）。
   在当前门表上都不成立；只有换相位多项式合成（少 ~95 个 AND 项）才可能同时降 C 和降并发。
4. 建议把 invsqrt 的资源重心放回 **C 面**（Toffoli 1,459.37 占 85.85%），
   宽度面按本页记录归档为已测边界。
