**同名类的语义**（都在 kernel 里用一个 `T ^=`/乘积形状的归一化窗口实测确认，示例见 §3）：

- **42 CCX = 一个 Toom-4 的 GF(2^12) 乘加**：42 个 rank-1 项，每项一次

- **24–41 CCX = 同一张量、更短的窗口**（学位更低的乘数），**不是**控制逻辑。
- **12 CCX = 量子掩码字 XOR**：`X(T)…; CX(T,B); CCX(A,B,T); CX(T,B); CX(t_k,b_k);

  （本线 11,160 T）**，`X` 取反 → `T ^= ~A & B`。
- **1 CCX = 单个 rank-1 项**：一次 AND 把乘积 XOR 进 7–12 个 consumer（
  `CX(T,x852)…CX(T,x863)` 这种），是"乘以一个线性/单比特操作数"时的最省形式。
- **Chien = 10-CCX 合取链 + 1 CCZ**：`R(A); CCX(b0,b1,A); R(T); CCX(A,B,T);
  R(x866); CCX(T,b3,x866); …; CZ(a0,b11)`，一次"12 位寄存器全零"判定，

## 5. 四类可移除冗余：全部为零

### 5.1 退化算符（本线首次测）

| 检查 | 结果 |
|---|---:|
| `CCX(a,b,t)` 中 a==b 或 a==t 或 b==t | **0 / 362,012** |
| `CCZ(a,b,c)` 中任两个相同 | **0 / 5,977** |

`CCX(a,a,t)` 会退化成 `CX`（省 1 T）、`CCX(a,b,a)` 会退化成 `CZ`（省 1 T），
tape 里一个都没有。

### 5.2 死目标（sound dead-code elimination，本线首次测）

判据（对每条轨迹都成立，与条件无关）：`CCX(a,b,t)` 只写 t，若 t 的**下一次 touch
是丢弃旧值的操作**（无条件 `R`；或一个结果位无人读的 `HMR`），则该 CCX 可删。

对全部 63,371,620 个 qubit-touch 建 `(qubit, op)` 有序表，逐条 CCX 查"目标的下一次
touch"：

```
dead_R_A (仅无条件 R 算丢弃)          0 / 362,012
dead_R_B (再把死位 HMR 也算丢弃)      0 / 362,012
目标此后不再被 touch                   0 / 362,012
```

结合 §3 的 next-touch 直方图，这是**结构性**的：每个乘积都立刻被消费，所以不存在
"算了没人用"的 AND。**-0 T。**

**死位 HMR**：71,994 个 `HMR` 的结果位，**0 个**的下一 touch 是无条件 `BIT_STORE0/1`
（即没有一个测量结果被丢弃）。所以也没有"测了不用"的 0-T 机会可转成 AND 的删除。

### 5.5 精确 splice 区间（全部低于 500 T，按要求**不实施**，只给判定路径）

**不是先验为假**，需要值级判据才能定：

|---|---|---:|---:|---|

判定程序（现成工具，本线未跑）：用 `qc.passes.measure_out.step_symbols` 的 64-bit 符号
代数把 `[A_end, B_start)` 扫一遍，要求该段所有被触碰的 qubit 在 B 入口的符号等于 A 入口
的符号（即中间那段是恒等映射在该段 support 上），且两段各自的 net 效应相同。
**上限收益 84+60+48 = 192 T = +0.0049 GM**，低于 500 T 报告门槛，也远低于一次丢 shot 的
−0.0428 GM——即使判定成立也不值得为它冒风险。列出来只是为了说明"这条路上确实没有大货"。

## 6. word 级活跃度：没有"纯线性寄存器"

75 个 word × 7 个 opcode 的完整表在 `residual.json:words`。要点：

- **`words_linear_only` = []，`words_never_touched` = []**：每一个 word 都被 CCX 触到

## 8. 这对 28.18 → 29+ 意味着什么

`GM ∝ (1/T)^{1/3}`，其它两条腿不动（base 28.180659，dqi 346,409,762,292.72）：

| 若省掉 | T 减少 | GM | ΔGM | 可行性 |
|---|---:|---:|---:|---|
| 最大一块精确重复段 | 186 | 28.1854 | +0.0048 | 不可行（跨 pass 重算） |
| 任务书的报告门槛 | 500 | 28.1935 | +0.0128 | — |
| 全部 12-CCX 掩码字 XOR | 11,160 | 28.4721 | +0.291 | 不可行（量子掩码） |
| 全部 4–11 乘积链 | 15,873 | 28.5962 | +0.416 | 不可行（rank-1 项计数） |
| 本线全部 38,052 个单乘积项 | 38,052 | 29.2331 | +1.052 | 不可行（同上） |
| 整个 Chien（已封） | 44,264 | 29.4138 | +1.233 | 已证不可行（dqi_chien） |
| **GM 29.0 所需** | **30,248** | 29.0000 | +0.819 | = T 的 8.24 % = 本线的 11.1 % |

**修正任务书里的换算**：T 每降 1 % 只值 **+0.095 GM**（不是 +0.33）；每降 10 % 值
+1.007 GM（这一条是对的）。500 T 值 +0.0128 GM，一次丢 shot 值 −0.0428 GM——
所以任何 < 1,678 T 的"冗余"都不值得为它冒一次丢 shot 的风险。

**剩余 T 的四个来源，以及各自的封闭理由：**

1. **134,660 T（49.4 %）乘积项**——42/24–41/13–23/4–11/3/2/1 各档合计。
   本线实测每一档的形状都是"k 个 rank-1 项 + CX 扇出"，k 就是该步乘法的
   bilinear rank。要减只有减项数：dqi_mult 的叶子秩穷举（µ₂(GF(8)) = 6）和
   dqi_algo 的 A4–A6 已经封死（rank 42→40 才 -6,136 T = +0.159 GM）。
2. **44,264 T（16.2 %）Chien**——11 T/位置 = `multi_controlled_x(12,1)` 的构造下界
   （dqi_chien 实测）。
3. **11,160 T（4.1 %）`T ^= A & B`**——12 个 AND 就是 12 位掩码的按位积，
   B 是量子态，不能经典化。
4. **82,588 T（30.3 %）单/短乘积链**——其中 38,052 个单 CCX 是"乘一个线性操作数"，
   已经是 1 个 AND 的最省形式；其余 2–23 项的链同理。

没有任何一类是"编译器可以少写一遍"的东西。这就是本线的答案。

## 9. 诚实的边界

- **验证范围**：没有跑官方 verifier（没有候选电路）；没有做任何量子态模拟。
  唯一的"动态"数据是 `Circuit.sample_toffolis(per_gate=True)` 的经典轨迹采样
  （32,768 shot，`se = 0.25 T`），用来做**平均执行 T 的归属**；它复现官方
  367,116.057 到 0.11 T。
- **`T_exact` 的加法闭合**：mine 268,419 + align 93,593 = 362,012（CCX）；
  mine CCZ 4,253 + align 1,724 = 5,977。两条都精确闭合，所以 272,672 这个数是
  逐条数出来的，不是比例摊的。
- **"没有冗余"的严格含义**：只对**已测的四类**（退化算符、死目标、异构重复段、
  同构乘法块）成立，且每一类的判据都是 sound 的（对全部轨迹成立）。它**不**排除
  需要重排/重写才出现的等价（例如把两次重复计算搬到一起、用第二条辅助线做
  retention），也不排除值级（模拟）的冗余——后者需要量子态模拟，本线不做。
- **E4 的 204,214 对**只覆盖 42-窗口和 24-窗口；更短的乘法块（13–23、4–11）
  没有逐窗口配对。但它们的 T 上限是 5,277 + 15,873 = 21,150 T，而 42/24 窗口
  （159,395 T 的绝大部分）已经测到 0 可合并。
- **任务书的两个乘法块数字互不自洽**：它说"3,793 个 42-CCX 块 ≈ 159,300 T"，
  但 3,793 × 42 = 159,306 已经超过 159,300，而且实测 42-块只有 **3,068 块 =
  128,856 T**（本线 2,999 + align 69，与 dqi_algo / dqi_mult 的 3,068 一致）。
  159,395 T 是 **≥24 CCX 的全部 3,972 个游程**（42 / 36 / 34 / 30 / 24 / 82 / 99），
  其中 42-块以外是 30,539 T。本文件的 3,068 / 3,972 / 159,395 是逐条数出来的。
- **被取代的 v1（诚实记录）**：kernel v1 的 `word_runs.per_region.*.size_hist` 与
  `T_blocks_ge24 / T_blocks_12` 两项聚合写错了（用 CCX 下标去索引"游程大小"，把
  `sum of size` 当成 T 的个数）。v2 改成按 run id 索引后，`n_blocks_12 = 963`、
  `T_blocks_12 = 11,556`、`n_blocks_ge24 = 3,972`、`T_blocks_ge24 = 159,395` 与
  dqi_algo 的 963 / 11,556 一致。**本文件所有数字来自 v2**；v1 的
  `artifacts/20261118_push_dqi_residual/out/residual.json` 只保留作对照，不要引用它的
  这两项。v1 的其余字段（区域、idiom、DCE、重复段、word 表、mean 归属）与 v2 相同。
- **簇表的 318 T 缺口**：簇的 T 取 `[首 CCX, 末 CCX]` 内的 Toffoli，落在簇间空隙的
  本线 CCZ 229 T + 89 T 其它不计；所以簇表只用来定位，不用来闭合（闭合用 §2 的
  `T_exact`）。
