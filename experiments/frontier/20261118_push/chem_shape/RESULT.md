1. **`(4,200,44)` 不可达，且不是优化问题，是算术。** 该形状 `K = R·C = 176`；`error_2`
   的最优 rank-176 逼近下界是 **143.97 mHa**，是 20 mHa 门槛的 **7.2 倍**
   **[bound]**。任何 `U`、`w`、`W`、任何训练时长都改不了这个下界。`(4,200,40)`
   （K=160）更差：205.01 mHa。简报里作为第二候选的 `(6,143,44)`（K=264）同样不可达：
   下界 **29.94 mHa** **[bound]**。
2. **能过精度门的形状必须 `K = R·C ≥ 352`。** 该族的“超出下界的结构余量”实测为
   12.8–14.1 mHa，且随 C 减小而增大；因此 `error_2 ≈ floor(K) + ~13 mHa ≤ 20`
   要求 `floor(K) ≤ 7`，即 `K ≥ 352`。`C=43`（K=344）实测 **21.2264 mHa**、
   `C=42`（K=336）实测 **23.2501 mHa**，都过不了门 **[measured-local, 与 Kaggle 复算一致]**。

3. **减 `R` 的路线被“合并一组就要丢 207–392 mHa 表示能力”封死**（`RESULT2.md`，
   用最优化 span 测得，不是初始化问题）。因此在“B=143 才能过门”的实测前沿上，
   `(8,143,44)` 就是整个合法族的成本最优点：**294,643,137.73，分数不变**。

## 1. 公开管线怎么工作（简报第 1 项）

`marculera/dfthc-compact-pipeline`（`dfthc_refit/`, git `704091bf…`, Apache-2.0）已解压读完；
`marculera/dfthc-merge-pipeline` 也读了。三问的答案：

### (a) `(R,B,C)` 是怎么被“compact groups”决定的

不是一个公式，而是**训练目标 + 调度**：

* 成本模型只读 `W.shape = (R,B,C)`（`verify.py:496` `rank_r,bases_b,ensemble_c = inputs.w.shape`），
  所以 `(R,B,C)` 是提交者声明的训练形状，成本按它计费。
* 公开管线从某个 seed 出发，按 recipe 里的 `shape = [R,B,C]` 做 **merge → shrink → refit**：
  `structure.py` 精确合并（两组 → 一组，`B` 相加、`C` 翻倍，块对角权重），
  `experiments/shrink.py` 逐级 fade 掉最弱的向量/份数再 L-BFGS 重拟合。
* “compact”指**每组只覆盖约 18 个有效轨道**（组间 profile overlap ≈0.13）。
  `experiments/compact_seed.py` 直接从 Hamiltonian 造 seed：对 multiplicity 加权目标做
  pivoted-Cholesky 叶子、按轨道 profile 做 balanced k-means 得到 R 组、每组用 OMP 选 B 个基、
  再用最小二乘解权重。这是公开件唯一不依赖公开权重的 4 组级起点（`(9,143,46)` 拟合到
  12.08 mHa，比 shrunk public seed 的 13.51 还好）。
* 关键结构事实（本轮核实）：**`B` 不是冗余填充**。`U_r` 是 `(B,76)`、行是单位向量但
  **非正交**（实测 143 行的奇异值 2.93…0.012），所以 `X_rc = Σ_b w_b u_b u_b^T` 被限制在
  该组 B 个 rank-1 投影子张成的 ≤B 维子空间里。真正的资源是**总投影子数 `R·B = rows−76`**，
  这正是 `RESULT2.md` 用最优化 span 测出来的结论（合并一对组损失 207–392 mHa）。
  也解释了为什么把 `U` 压缩到 76 维“无损失重基”不成立：那会丢掉 143 维 span 的覆盖。

### (b) 角度表（`angle_words`）怎么从 `U/W/H2_I` 生成

**闭式，只由 `U` 决定，与 `W/H2_I` 无关**：

* 行数固定为 `N + R·B = 76 + R·B`：前 76 行是一体向量，后 `R·B` 行按 `(rho,b)` 排列。
* 每一行是一个 76 维单位向量；在固定 `tree_edges`（75 条边、根 0、父先子后）上，
  按 `reconstruct_u_vectors` 的顺序做 75 个 Givens 旋转，就得到 75 个角
  `θ/π = word / 2^(brot−1)`，即 `angle_words` 是 `round(θ/π·2^(brot−1))`。
  这是可逆的编码（`encode.py`）；`brot=8` 时 `decode(encode(V))` 与 `V` 的偏差是 0
  （公开件与我们的 stage-1 都实测过）。
* **`W` 和 `H2_I` 不进角度表**，它们只进 `Lambda`、`E_gap`、`error_1` 和 `error_2` 的
  `X` 重构。所以：换 `C` 或换 `w/W` 不需要新电路；换 `U` 或换行数必须重发 15 个
  `angle_k_*.kmb`。这一点对成本搜索是决定性的（见 §4）。
* 优化（Adam / float64 L-BFGS / Gauss-Newton）作用在 `U, w, W` 上，目标是对
  `(U,w,W)` 的 `ε_fro + κ·D(w)`；`quantize.py` 做渐进量化（按影响排序、每次冻结一部分）、
  `polish_words.py` 在量化后做 ±1 的精确坐标下降，`refit_weights.py` 在固定 words 下重解
  `(w,W)`。**量化损失 ≈3–4 mHa**（shipped 的 20.0 vs 同形状连续拟合 16.55），
  这就是为什么公开管线要求“量化前 ≤16.5 mHa”。

### (c) 需要的输入

* 比赛的 `FeMoCo76o113e.fcidump`（打包、SHA-256 校验）+ 官方 fixed shifts
  `FeMoCo76o113e.fixed_shifts.npz`（`Hsym_lower`、`H1_I`；提交里的同名键会被**替换**，
  即 `S`/`beta_1` 总是 baseline 的）。
* 一个 seed factorization（`U (R,B,76)`, `W (R,B,C)`, `H2_I (R,C)`；`H1_I` 标量、
  `Hsym_lower (2926,)`）。
* 训练时公开管线还要求 starter kit / `kickmix`，但**评分只需 numpy**：本轮所有数字都是
  numpy + 官方 `scoreinfra` 代码算的。
* 我们的实际血统（比公开 compact 管线更直接）：shipped npz 是 `marculera/dfthc-c44-build`
  的 `(8,143,44)` 表（8-bit words，XOR-of-five 码，4,022-Toffoli loaders），权重
  `W/H2_I` 由我们自己的 `refit_grg.py` 重解到 `Λ=283.1458`、`error_1=error_2=0.0199999997`。
  电路=那个公开件原样（sha `ed648708…`），**不是**我们 `code2` 编译器产的。

## 2. `(4,200,44)` 为什么不可能：秩下限

`error_2` 的精确形式（官方 `dfthc_math.py`）：

```
error_2^2 = || Σ_{r,c} X_rc ⊗ X_rc − T ||_F^2 ,  T = tei + (S⊗I + I⊗S)/2
```

在 vech 基（2926 个轨道对，带 √2 权重）里它就是
`|| Σ_i x_i x_i^T − H ||_F^2`，`i=1..K`，`K=R·C`。任何 `Σ x x^T` 都是 PSD 秩 ≤K 矩阵，
所以最优误差 ≥ H 的截断尾（Eckart–Young；负特征值无法被 PSD 和匹配，按平方计入）。
这是对**所有**分解的下界，不是对某个优化器的下界。

| K = R·C | 达到它的形状示例 | `error_2` 下界 [bound] | 20 mHa 门 |
|---:|---|---:|---|
| 160 | (4,200,40) | **205.01 mHa** | 10.3× 不可能 |
| 176 | **(4,200,44)** | **143.97 mHa** | **7.2× 不可能** |
| 264 | (6,143,44) | 29.94 mHa | 1.50× 不可能 |
| 280 | (8,143,35) | 23.33 mHa | 1.17× 不可能 |
| 288 | (8,143,36) | 20.51 mHa | 1.03× 不可能 |
| 296 | (8,143,37) | 17.94 mHa | 仅当几乎贴住下界 |
| 320 | (8,143,40) | 11.74 mHa | 需 1.7× 下界 |
| 344 | (8,143,43) | 8.17 mHa | 实测 21.23（失败） |
| **352** | **(8,143,44) 现役** | **7.36 mHa** | 实测 20.00（PASS） |

所以简报的整张“形状省 8–9%”表在 `R·C < 352` 的所有行上都不成立：那些点连
`error_2` 的物理下界都过不了 20 mHa，`Lambda/λ_eff` 更不用谈
（C=43 的 Λ 实测 534，`RESULT3.md`）。

## 4. 重新算的成本（简报表的修正）

成本两块：`T = angles_toffoli + T_h`，`Q = heuristic_persistent + J·brot + max(temp, 77)`。
`angles_toffoli = 2·L`，`L` 是每趟 15 个 loader 的静态和。现役 `L=4,022`（rows=1220）。
两种装载器模型：

* **lin**（乐观，简报隐含的假设）：`L = 4022·rows/1220`。
* **cons**（保守，冻结 products=193）：`L = 15·(6 + high(rows) + 193)`；
  `high(1220)=69` 时给 4,020 ≈ 实测 4,022，**与现役点自校准**。

`B≥129` 是硬约束。）

要点：

1. **简报表低估了节省**：它把 `angles_toffoli` 固定在 8,044。真实 `(4,200,44)` 的
   rows 是 876，角度 T 只有 5,776（lin）→ `T=11,403`，不是 13,671。
2. **但 lin/cons 的差距是 226.9M vs 259.4M**，装载器模型决定一切；而 rows≠1220 的
   loader **不存在**。我们 `code2` 规划器在 1220 行表上最好 4,017（−5），
   两次 Kaggle 尝试（15 min 和 1.5 h/loader）都没找到完整 plan（`RESULT6.md`）；

3. 唯一“无需新电路”的轴是 `C`（words 只编码 `U`）：`C=43` 省 78 T（−0.5%，
   293.1M），`C=42` 省 157 T（−1.1%，291.5M），但两者都实测 `error_2>20 mHa`
   （21.2264 / 23.2501），且 `C≤36` 被秩下界直接判死。**此轴封闭。**

## 5. 为什么没有构建候选 / 没有官方 verifier 运行

* **没有合法输入。** 唯一可能低于目标的形状都需要 `K=352` 且 `B<143`（实测失败）
  或 `R<8`（合并损失 207–392 mHa），而 `(4,200,44)` 这类形状被秩下界判死。
  没有任何 `(U,w,W)` 可以在 20 mHa 内表示目标。
* **即使有，也发不出电路。** rows≠1220 必须重发 15 个 `angle_k_*.kmb`；
  `code2` 编译器硬编码 1,220 行 / 77 个 high / 11 个 selection 位，公开 emitter
  密度 2.4×。在 3 小时窗口内无法完成“拟合 + 量化 + 发射 + 官方验证”四步。
* 因此本轮**没有** `submission.npz` 候选、没有 `.kmb`、没有跑官方 verifier。
  不把未执行的验证写成通过；不打包、不提交。
