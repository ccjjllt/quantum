# RESULT — chem `Λ` 是否还有 refit 空间（2026-11-18）

**结论：关闭。** 在官方固定 shift（`S`, `beta_1` 由 `fixed_shifts.npz` 强制）下，`lambda_eff`
有一个**与提交无关的硬下界 46.78618**；我们现在的 46.92172 是它的 **1.00290 倍**。
整条 chem-`Λ` 轴剩余的全部价值是 **+0.0272 GM**，而且要拿它必须重发 15 个 loader。
不建议再做。

所有数字都是 **Kaggle CPU**（`zhuating/qcc-chem-lambda-axis`，`enable_gpu=false`）上用
**未修改的官方 verifier 代码**（`dfthcsos.verify.evaluate_words` / `scoreinfra.dfthc_math`）
测出来的；控制组逐位复现 shipped 包。本地只做小数组算术（npz 里 `W/H2_I`，无积分）。

## 1. 直接回答两个问题

| 量 | 值 | 占比 |
|---|---:|---:|
| `Lambda` | **283.145810612929** | 100 % |
| `lambda_h1 = Σ|eig(h1_prime)|` | **13.028793638** | **4.60 %** |
| `lambda_h2 = 0.25 Σ_(ρc)(‖w‖₁ + |H2_I|)²` | **270.117016975** | **95.40 %** |

所以第 1 问不是「lambda_h1 占大头（>80%）」的情况 —— **lambda_h2 占 95.4%**。
但第 2 问的答案是：**lambda_h2 已经贴着它的代数下界**，压不出东西。

```
0.25 · Σ_(ρc) W_ρc²  = 269.962008210        (W = H2_I − Σ_b w，即 Qaggle 的 identity offset)
lambda_h2            = 270.117016975
超额                 = 0.155008765   = lambda_h2 的 0.057 %，Lambda 的 0.055 %
```

这 0.155 就是 `|s| + |h| ≥ |s − h|`（s = Σ_b w，h = H2_I）的全部松弛量：我们的 w 已经
在 352 个 `(ρ,c)` 里几乎逐格单符号（`Σ|w|₁ − Σ|Σ_b w| = 0.205`），`sign(H2_I) = −sign(Σ_b w)`
在 **348/352** 格成立。把它完全压到 0.25Σ W²：

```
Lambda 283.145811 → 282.990802      lambda_eff 46.921717 → 46.908782
cost   294,643,137.73 → 294,561,913.59   GM 28.150932 → 28.153519   (+0.00259)
```

**+0.0026 GM。** 这就是「把 lambda_h2 压到下限」的全部收益。原因是 lambda_h2 不是自由参数：
它被 `E_gap` 的反解钉死了（下一节）。注：这 0.0026 需要动 4 个 `(ρ,c)` 的 `H2_I`
（改变 `h1_prime`，因此 `error_1` 要重测；`error_2` 不受影响）。**没有实测**，因为
收益只有 2.6e-3 GM，不值得一次 kernel。

## 2. 为什么钉死：`E_gap` 与 `lambda_h2` 是同一个 `‖W‖²`

官方源码里（`dfthc_math.evaluate_dfthc_vectors`）：

```
E_SOS = ecore − η·β1 − (lambda_h1 − Tr h1_prime) − 0.5·‖W‖²
E_gap = UPPER − E_SOS = C + 2·Σ_(λ<0)|λ| + 0.5·‖W‖²
C     = UPPER − ecore + η·β1
```

`C` 只依赖固定 shift 与 FCIDUMP ⇒ **对所有提交都是同一个常数**。本 kernel 实测：

```
C = −559.1324731485038       (UPPER = −22140.27335, ecore = −21021.2140122, η·β1 = 559.926864651)
E_gap(identity) = 3.9148980002669305    官方 E_gap = 3.9148980002646567     (差 2.3e-12)
```

`h1_prime = A − G`（`A = H1_THC − (η/2)S + β1·I` 固定，`G = Σ W_ρc X_ρc`）的构建与官方
`build_h1_prime` **逐位相同**（`max_abs_diff = 0.0`）。

把两件事合起来（`P := Σ_(λ>0) λ ≥ 0`，`Neg := Σ_(λ<0)|λ|`，`Λ_H1 = P + Neg`）：

```
Λ_H2 ≥ 0.25·‖W‖²                       （上面那条三角不等式，实测比值 1.000574）
2Λ − E_gap ≥ 2Λ_H1 + 0.5‖W‖² − E_gap = 2Λ_H1 − C − 2·Neg = 2P − C ≥ −C
⇒  lambda_eff ≥ sqrt( E_gap_floor · |C| ) = sqrt(3.914898 × 559.132473) = 46.78618
```

这是**与提交、与 (R,B,C)、与 w/H2_I/words 全都无关**的下界（只要 shift 是官方固定的）。
等价地，在 E_gap 贴地（我们已贴地，3.9148980003）且 lambda_h2 饱和时有精确恒等式

```
Λ = (E_gap − C)/2 + P = 281.523686 + P
```

实测 `P = 1.467116`（`h1_prime` 谱：`min −0.7556`、`max +0.4174`、`Tr = −10.0946`、
`Neg = 11.5617`）⇒ 281.5237 + 1.4671 = 282.9908，再加 0.1550 的三角松弛 = **283.1458**
—— 与官方 Λ 完全吻合。

**因此：Λ_H2 不是「能 refit 的 95%」，它是被 E_gap 反解出来的 95%。** 想降 Λ 只剩一条路：
把 `P` 压到 0（等价于让 `h1_prime ⪯ 0`，需要 `G ⪰ A`，只能用 352 个 `H2_I` 偏移），
上限就是上面的硬下界：

```
Lambda 283.145811 → 281.523686 (−0.573 %)   lambda_eff 46.921717 → 46.786180 (−0.289 %)
cost   294,643,137.73 → 293,792,036.88       GM 28.150932 → 28.178090   (+0.0272)
```

**整条轴 ≤ +0.027 GM，且 P = 0 已经是这个方向的极限。**（`P` 不可能为负。）

## 3. 实测：Λ 的自由度到底在哪

`Λ = lambda_h1 + lambda_h2`；`lambda_h2` 只由 (`w`, `H2_I`) 两个 **npz 里的普通经典数组**
决定，与电路无关；`lambda_h1` 由 `h1_prime` 的谱决定，即由两体向量解码出的 `X` 决定。

| 探针（官方 `evaluate_dfthc_vectors`） | Λ | ΔΛ | error_1 | error_2 |
|---|---:|---:|---:|---:|
| shipped（控制） | 283.14581 | 0 | 0.0199999997 | 0.0199999997 |
| **76 条一体行 words 全部置零** | **283.14581** | **0（逐位相同）** | 10.1845 | 0.0199999997 |
| 两体 words 每 7 列 +1 | 287.40747 | +4.2617 | — | 0.42437（FAIL） |
| 两体 words 每 7 列 −1 | 287.10014 | +3.9543 | — | 0.42585（FAIL） |
| 两体 words 全随机 ±1 | 289.73644 | +6.5906 | — | 0.46768（FAIL） |

结论（对应任务书第 2 步）：

1. **Λ 与 76 条一体行完全无关**（置零后 Λ 逐位不变）。一体行只影响 `error_1`。
2. **Λ 不是「只由 W 决定」，但也不是由 words 决定**：它由 (`w`, `H2_I`) 决定，
   而这两个都是 npz 里的纯经典数据（电路不加载它们，`T/Q` 也不看它们）。
   words 只能通过两体 `X` 改 `lambda_h1`，而且**只能改坏**（任何 ±1 扰动都让 error_2 爆到 0.42+）。
3. 官方 shift 强制 `S`/`beta_1`，`beta_1` 这个本来最强的旋钮被拿走了 —— 这正是硬下界的来源。

## 4. 与三份公开件的对照（解释「Λ 几乎不动」）

`C` 对所有提交相同 ⇒ `Λ ≥ 281.5237` 对**所有人**成立，公开件的 Λ 就是 `281.5237 + P_公开`：

| 件 | Λ | 反解 P | error_1 |
|---|---:|---:|---:|
| 我们 (8,143,44) | 283.146 | 1.47 | 0.0200 |
| 公开 A | 287.41 | 5.88 | 0.0104 |
| 公开 B | 290.45 | 8.92 | 0.0110 |

它们精度好一倍、C 更大，却只把 Λ 抬上去（`P` 更大）—— 与恒等式一致。
**在这条轴上我们已经是最优的一份，且离硬地板的距离只有 0.58 %。**

## 5. 交付判定

- **关闭 chem-Λ 轴。** 剩余 ≤ +0.027 GM（0.29 % 的 `lambda_eff`），且需要
  ① 用 352 个 `H2_I` 解一个 `G ⪰ A` 的可行性问题，② 重新编码 76 条一体行（新 `h1_prime`
  的本征向量），③ 用 `emit_plan.py` 重发全部 15 个 loader。收益/工作量严重不成比例。
- **没有跑 P→0 的优化搜索**（按协调者指令：第 1 问已判定关闭，不再搜索）。
  上界 +0.027 GM 已由恒等式给出，不需要搜索来确认。
- chem 腿剩下的杠杆只剩 **T（loader Toffoli）与 Q（qubit）**，`lambda_eff` 已经没有空间：
  99.71 % 的可用下限已经拿到。
- `error_2` 在本轴的任何操作下都逐位不变（`w` 不动）；`error_1` 是唯一需要重测的量。
