## Notes

- Pipeline `main.py` enforces `decision=SUBMIT` only on all-PASS + GM >= 28.09490;
  this run met it, so a zip was packaged. Fallback `703843d3` (GM 28.131370649)
  was not used.
- **v7/v8/v10 failure postmortem (same root cause, no slot spent):** all three errored
  in `stage_members` with `missing: ['dfthcsos/submission.npz']` although the file was
  mounted with the right size. Cause: a transcribed chem SHA-256 in `main_template.py`
  was 63 hex chars (`…cf8cac4cce…` instead of `…cf8cac44cce…`, one dropped `4`), so the
  content lookup missed while the size pre-filter hit. Fixed in v11; `make_main.py` now
  asserts every pinned hash is 64 hex chars, and `stage_members` prints every
  size-matching candidate (`size sha→match path`) plus unreadable files to the kernel log
  (retrievable via `kaggle kernels logs` even on ERROR) and retries hash reads 4x.
  v9 was a COMPLETE diagnostic kernel (input tree lister, `diag.py`, code_file restored
  to `main.py` afterwards) that confirmed the mount was intact.
- No local simulation was run for grading; only SHA/size checks, GM arithmetic, and
  Kaggle CPU execution.
