# 实验记录

这里放研究笔记、小型探索脚本和结果索引。先完成实验，再决定是否值得抽成公共代码；不为一次性探索搭建测试或门控体系。

每次研究只需留下：

- **假设**：想降低什么成本，为什么这个改动可能有效。
- **改动**：代码、参数、输入和参考版本。
- **观察**：资源数字、误差、运行耗时或失败原因。
- **证据**：候选电路与手动运行的日志位置，必要时加 hash、salt 和工具版本。
- **下一步**：保留、放弃，或继续哪个方向。

建议名称为 `YYYYMMDD_task_short-name`。小型源码和笔记可放同名目录；大电路、权重、日志放到 `artifacts/<实验名>/`，最终 ZIP 放到 `submissions/`。不要将 Kaggle token 写入源码、笔记或结果。

## log.csv

[log.csv](log.csv) 初始只有表头，不预填不存在的实验。每完成一次有结论的尝试，增加一行；字段含义如下：

| 字段 | 内容 |
| --- | --- |
| `date` | 北京日期或带 `+08:00` 的时间 |
| `task` | `invsqrt`、`dqi`、`dfthcsos` 或 `combined` |
| `experiment` | 简短且唯一的实验名 |
| `hypothesis` | 本次要回答的问题 |
| `change` | 核心代码/参数改动 |
| `result` | 实际观察到的结论，包括负结果 |
| `cost` | 子任务 verifier 成本，越低越好；未测则留空 |
| `improvement` | 与明确参考成本之比；未计算则留空 |
| `verification` | 实际执行了什么，例如静态查看、官方 verifier 全量运行及 salt；未验证写明 |
| `artifact` | 对应电路、日志或笔记路径 |
| `notes` | 版本、hash、耗时、线上分数或下一步 |

所有检查都手动发起。记录应如实区分“生成完成”“静态统计”“本地 verifier PASS”和“线上提交成绩”。只运行一项或缩小规模时，写明范围；不将快速探索结果标成完整验证通过。

总榜 GM 与子任务成本使用不同口径，作者自报 LB 也单独注明。比较不同方案时尽量保持官方 verifier、依赖、参数和 salt 一致；近似 DQI 的最终候选可手动增加不同 salt 的测量。
