## 结论

**本轮没有生成 61Q 候选，也没有可执行的全尺度验证。**
但阻塞点被定位到一个具体、可复核的位置，而不是"峰值太多"：

1. `Q` 是**电路里出现的量子线下标数**，不是同时存活值的峰值。要降到 61 必须让某一条线的
   下标在全部 49,051 条指令中都不再出现，而不是只把它在某段变空闲。
2. 用户给的"paid uses 最少"（q49 27、q34 29、q53 30、q35 32、q33 32）不是可消去性的度量。
   这五条都是**乘法累加器**（linear form + `CCX` 累加），总使用 1,326–1,692 次；
   paid 少只是因为它们多用作 `CX`/`CZ` 的免费控制。
3. 用**值活跃性**（一次写入到下一次写入前最后一次读取）重算，62 峰值的范围从旧保守模型的
   19,143 条指令 / 98 段缩小到 **2,550 条指令 / 58 段**。旧模型把"停着不用的缓存值"也算成占用。
4. **没有免费消去**：在峰值指令 op15283，62 条线的值在全部合法 x 上两两不同；五个候选线加上
   q23 没有一个等于另一条线、其补、或任意两条线的 AND/XOR。
5. `HMR` 是 **Hadamard + 测量 + 复位**：结果是与状态无关的均匀随机硬币，相位回踢是
   `π·m·(测量前的值)`。因此**不能把一条活线的值测成经典位再恢复**（这正是选项 (c) 走不通的原因）；
   同一 x 在不同测量分支上同一条线的值不同：q50/q41 在 op28380 的全 0 分支上恒 0，
   在 6 个随机分支上约一半 x 为 1；q23 在 op28415 上全 0 分支只有 6/512 个 x 为 1，随机分支约一半。
6. 唯一有希望的架构是"暂停 + 重新分配寄存器"。**免费暂停**（下一次触碰就是重新初始化）
   覆盖 2,550 个峰值指令中的 **1,918** 个；再加 9 个 1–2 线可重建的暂停
   （q28 在 `[15723,15914)` 的 8 段、q50 在 `[23855,23863)` 1 段）覆盖到 **2,103/2,550，代价 9C**。
   剩余 447 个峰值指令所在的区间，唯一能整段暂停的线是 **q23**（`[16731,18483)` 内其余 39 条
   scratch 线全部被触碰）。
7. 而 q23 在 `[16199,24922]` 上不动，下一次触碰是 op24922 `CCX q23 q1 q18`（q23 作控制）。
   该处 q23 的值**不是**任何一条线、其补、任意两条线的 AND/XOR（全域），也**不是**三条线的
   两门表达式（512 x 抽样）。显式反例：`x=335840` 与 `x=1343360` 其余 61 条线逐位相同
   （61 位整数 `62088118648576`）而 q23 为 1/0；全域共 612,723 对这样的冲突。
   所以 q23 在 op24922 不是其余 61 条线的函数，重建它没有便宜 gadget，
   而预算法只留下 k < 16.83C。

因此：**在"保持原门序列、只做值保持改写"的范围内，61Q 的已知最便宜方案用 9C 可以覆盖
2,103/2,550（82.5%）的峰值指令，但剩下的 447 条需要一个 q23 重建 gadget；
没有找到 ≤16.83C 的这种 gadget。** 保持 62Q 仍是已知最便宜的选择（97,700.776777236）。

**续（第 8 节）：非线性重建也没有解决它。** 在阻塞区间出口处，候选线的值**没有非平凡仿射覆盖**
（不是任何一族仿射型的 AND），所以连"单积"都不可能，更谈不上 k 个乘积。
代表指令 op16750/16887 处确实找到 1-CCX 的 20 项线性型乘积（q20/q25/q26/q27，三分支全域验证），
但这些线在阻塞区间内被触碰、不能整段停放。最终覆盖 **2,172/2,550、25 C**（预算内），
仍差 378 个峰值指令，**没有 61Q 调度**。

**续（第 7 节）：交换/重排路线也没有解决它。** 用精确基态交换判定（`commute.py`）测试把
某条线在 `[16731,18483)` 的触碰整体移出：39 条被触碰的 scratch 线**全部失败**，
最小阻塞集是 **13 条把累加器当控制的门**（`CX q14 q46`、`CX q16 q14`、`CCX q15 q16 q20` 等）。
按峰值块放宽后，重排只额外换来 **114 个指令 / 8 个块 / 0 C**；与暂停方案合并是
**2,157/2,550、9 C**，仍有 393 个指令没有机制，**因此仍没有 61Q 调度**。
重排本身已用 `validate_reorder.py` 端到端核对（14 个 x 的逐 shot 相位一致）。

## 1. 口径与预算法

官方计费（`data/competition/verifiers/invsqrt/verify_submission_invsqrt.py`）：
`C = E[CCX+CCZ+CSWAP] + E[T]/4 + E[一般旋转]·(0.56·log2(1/eps)+5.3)/4`，`score = Q·C`。
付费门是 `CCX`、`CCZ`、`CSWAP`；`X/Z/CX/CZ/SWAP/NEG/R/HMR*` 与经典位操作不计费。
经典条件成立才执行；量子控制为 0 的付费门仍计费。

沿用已保存的完整官方本地结果（本轮不重跑）：62Q，C=1,575.818980278，
score=97,700.776777236，200,540,928 shots，PASS。
61Q 打平条件：

```
61 · (C + ΔC) < 62 · C   =>   ΔC < C/61 = 25.833098 C
```

## 3. 62 峰值到底是什么

### 3.1 保守模型 vs 值活跃性

- 保守模型（触碰→无条件复位）：峰值 62，19,143 条指令，98 段。
- **值活跃性**（写入→下一次写入前最后一次读取）：峰值 62，**2,550 条指令，58 段**
  （`value_liveness.json`、`peak_blocks.py`）。
  最长四段：`[27551,28372)` 821 条、`[17576,17806)` 230 条、`[15691,15915)` 224 条、
  `[17849,18007)` 158 条。

活跃性直方图（按指令数）：62→2,550；61→11,983；60→1,711；59→2,019；58→2,726；…；
大量区段只有 30–50 条线。也就是说 62 只在 5.2% 的指令上出现。

### 3.2 峰值处没有免费别名

`alias_scan.py`：对全 3,133,452 个合法 x（固定全 0 HMR 分支），在每条候选线的**每一次使用**处
与其他 61 条线逐位比较。结果（匹配次数 / 总使用）：

| 线 | 有别名 | 全为常数的使用 |
|---|---:|---:|
| q49 | 2/1564 | 2 |
| q34 | 5/1692 | 5 |
| q53 | 2/1326 | 2 |
| q35 | 5/1528 | 5 |
| q33 | 4/1666 | 4 |
| q23 | 10/270 | 11 |

所有命中都出现在"该线与另一条线同时恒为 0"的退化点上，没有一处是真正的复制关系。

`span_test.py`（512 x × 2 个 HMR 分支，GF(2) 线性张成）：一条线是其他线 XOR 的比例：

- q40 2,005/5,110（39%）、q28 929/4,680（20%）、q50 335/4,516、q27 228/5,168、
  q34 198/3,384、q22 178/5,654；
- q49 32/3,128、q53 98/2,652、q35 52/3,056、q33 82/3,332、q23 61/540、q59 6/1,438。

没有一条线在多数使用处是线性型。

`cheap_expr.py` 在 op15283（`CX q50 q28`，峰值第一段起点）对全合法域逐位检验：
q49、q34、q53、q35、q33、q23 **没有一条**等于另一条线、其补、任意两条线的 `AND`/`AND¬`/
`XOR`/`XNOR`。op15283 处 62 条线**两两不同**（`collision_op15283.json`，0 对相等）。

### 3.3 HMR 的语义（这条决定了选项 (c) 不可行）

`probe_classical_phase.py` 与手工探针（`.venv/bin/python`，原生 kickmix，batch 1024）：

| 电路 | 末相位分布（半 turns） |
|---|---|
| `X q1; Z q1` | `{1: 1024}` |
| `X q1; HMR q1 b0` | `{0: 506, 1: 518}` |
| `X q1; HMR q1 b0; X q2; Z q2 if b0; X q2` | `{0: 1024}` |
| `CCX q0 q1 q2; HMR q2 b0; CZ q0 q1 if b0` | `{0: 1024}`（三种输入真值都如此） |
| `X q22; HMR q22 b0` 的经典位 | 0/1 各半 |
| `HMR q22 b0`（q22=\|0\>）的相位 | `{0: 1024}` |
| `HMR q22 b0; X q3; Z q3 if b0; X q3`（q22=\|0\>） | `{0: 506, 1: 518}`：位是随机的，所以条件 Z 随机开火 |

判读：`HMR` = Hadamard、测量、复位。**测量结果与状态无关，是均匀随机硬币**；相位回踢为
`π·m·v`（v 是测量前的值）。`R` 对 |1> 也给出随机相位。所以：

- 不能把一条活线的值测成经典位再"用 `X if b` 恢复"——b 不是那条线的值；
- 无相位代价的暂停只在"下一次触碰是重新初始化"时成立；否则必须像基线那样用
  `CZ 因子 if m` 做修复，而修复需要那个值本身。

`multibranch.py`（6 个 HMR 分支，全合法域）：op28380 处 q50/q41 在全 0 分支上恒 0、
在随机分支上约一半 x 为 1；q23 在 op28415 处全 0 分支上只有 6/512 的 x 为 1（近似稀有但非常数）。
**"某条线在这段恒 0"不是结构事实**，不能据此删门或换线。

## 4. 唯一可行架构：暂停 + 重建寄存器

### 4.1 为什么只有这条路

`Q` 是下标计数，所以必须整条线消去；而在 op15283 这类峰值指令上 62 个值两两不同、
又没有别名/线性替代（3.2 节），只能把某个值**暂停**（测掉）再在峰值之后**重建**，
使同时存活值降到 61，再按区间着色重排 61 个寄存器。

`park_cover.py` 把 2,550 个峰值指令当覆盖问题：每条线的两次相邻触碰之间是一个可暂停的空隙
（整段不被触碰）。若**只按暂停次数**计（每次 ≥1C），贪心 4 次即可覆盖全部峰值
（q23 `[16199,24922]`、q23 `[27188,28415]`、q43 `[15211,16222]`、q24 `[25235,27535]`），
所以"58 段峰值必然超过预算"不成立。真正约束是重建值能不能算出来，不是暂停次数。

`park_cover_cost.py` 加入代价模型（下一次触碰是 `X/R/HMR`、`CCX` 目标、`SWAP` 或线性型 → 0C；
是读取 → ≥1C）：

- 446 个免费空隙覆盖 **1,918/2,550** 个峰值指令；
- 剩余 632 个指令分布在 `[15285,15341]`、`[15447,15551]`、`[15594,15613]`、`[15691,15915)`、
  `[16058,16091)`、`[16711,18483)`、`[23857,23859)`。

### 4.2 剩余 632 个指令的重建筛查

`park_rebuild_screen.py` 对覆盖这些指令的 **1,352 个 (线, 空隙)** 逐个在 512 x 抽样上测
"重建值是否为常数/另一条线/两条线的 AND 或 XOR"：

- 0 个免费选项；
- 只有 10 个 1C 选项：q28 在 `[15723,15914)` 的 8 段（贡献 72+17×6+9 = 183 个指令）、
  q50 在 `[23855,23863)`（2 个）、q51 在 `[23856,23860)`（2 个）。

贪心合计：**2,103/2,550 个峰值指令，代价 9C**。剩余 447 个指令，
主要是 `[16731,18483)`（330 个）和 q28 空隙的边界点。

### 4.3 最具体的阻塞

`[16731,18483)` 这 1,752 条指令内，**只有 q23 一条 scratch 线完全不被触碰**
（其余 39 条全部至少触碰一次）。q23 的空隙是 `[16199,24922]`，下一次触碰：

```
op24922   CCX q23 q1 q18      # q23 作控制，值来自 op16188-16189
```

对该点的全合法域检查（`cheap_expr.py`）：q23 的值不等于任何单线/补/双线 AND/XOR，
也不等于任何三线的两门表达式（512 x 抽样）。也就是说，要暂停 q23 必须重建它在 op16189
写下的、跨 8,723 条指令不变的分支相关值，而没有 ≤2 门的表达式。

**显式反例（本轮新增）**：在 op24922，`x=335840` 与 `x=1343360` 的其余 61 条线逐位完全相同
（61 位打包整数 `62088118648576`），q23 分别为 1 / 0；全合法域上共有 **612,723 对**这样的
相邻冲突（`artifacts/20261106_q61/collision_op24922.json`）。
所以 q23 在 op24922 **不是其余 61 条线的函数**：任何"只靠其余线重建 q23"的 61Q 方案在该点必然失败
（该结论在固定全 0 HMR 分支上成立；由于 `HMR` 是随机硬币，它也足以否定任何分支无关的重建函数）。

同一区间其他分块的可暂停线（q42@16877、q22@16963、q31@16965、q37@17413、q61@16886）
在全合法域上同样**没有**任何单线/补/双线 AND/XOR 表达式（`cheap_expr.py` 逐个 0 命中）。
所以 `[16731,18483)` 这一段不是"选错了线"，而是没有任何一条线能在那里便宜地重建。

计量口径验证：把基线 KMX 中所有含 `q61` 的行删掉后重新解析得到 `num_qubits=61`；
删掉 `q23` 的行仍是 62（因为最高下标仍是 q61）。也就是说要降 Q 必须让某一**下标**完全消失
（其余线整体下移一位是免费重命名）。

代价账：9C（已找到的暂停）+ k（q23 重建）要 <25.8331C，即 **k < 16.83C**。
若 q23 的重建能用一个 ≤16 门的 gadget 完成，61Q 就成立
（61·(1575.8190+9+k) 对 62·1575.8190）。本轮没有找到这样的 gadget；
`[16731,18483)` 的 330 个指令也没有第二个可整段暂停的线。

## 5. 未采用/被否定的其他改写

- **(a) 按需重算**：每条候选线有 1,326–1,692 次使用，其中 paid 只有 27–32；
  在 2,550 个峰值指令上不存在空闲线可放临时量，所以只能在峰值段外做整段暂停+重建
  （第 4 节），而不是逐次重算。
- **(b) 吸收进输出线/已有缓存**：op15283 处 62 条线两两不同；五条候选线在全部使用处
  没有一条与别的线逐位相同（只有两处"全体为 0"的退化点）。没有可吸收对象。
- **(c) 换成经典奇偶/条件**：`HMR` 的结果是随机硬币（3.3 节），活线的值无法测出；
  同一个 x 在不同测量分支上线的值不同，所以也不存在"只是当前测量结果的函数"的表示。
  线性的（XOR）替代只覆盖 2%–39% 的使用处。
- **(d) 改调度让峰值不需要它**：第 4 节就是这条路。免费暂停 + q28 暂停覆盖 2,103/2,550；
  剩下的 447 个指令只能靠 q23 的重建。

## 7. 交换 / 重排路线（2026-11-06 续）

第 4 节的结论建立在"保持现有门序"上。本节测试另一种可能：把某条线在 `[16731,18483)`
里的触碰**整体交换到区间外**，这样它在区间内没有任何值要保留，寄存器自然空闲，代价只有重排。

### 7.1 判定方法（精确，可复核）

新增 `commute.py`：两条门的交换性用**基态穷举**精确判定——在两条门支持集的并（≤6 个量子位，
≤64 个基态）上分别按两种顺序施加，比较最终比特与累积相位。这比"支持集不相交才交换"强得多，
例如所有 XOR 进同一目标的门（`CX a t`、`CX b t`、`CCX x y t` …）互相交换。
`HMR`/`R` 当作**屏障**（不与任何门交换），条件门另外要求其经典位（和条件栈）在移动路径上不被改写，
目标位置的条件栈必须与原位置相同。

`commute_scan.py` + `commute_blockers.py`：对区间内每条 scratch 线的每次触碰，分别测试
"能否移到区间左端之前 / 右端之后"。

### 7.2 区间级结论：没有任何一条线能整体移出

区间 `[16731,18483)` 共 1,752 条指令：`CX` 1,709、`CCX` 19、`X` 16、`HMR` 4、`R` 4。
39 条 scratch 线被触碰（q23 唯一不触碰）。**39 条全部无法整体移出**：
每条线都有至少一次触碰左右都动不了。例如

| 线 | 区间触碰 | 可左移 | 可右移 | 第一个双向卡住的触碰 |
|---|---:|---:|---:|---|
| q31 | 74 | 0 | 0 | op16753 `CX q31 q46` |
| q42 | 37 | 0 | 0 | op16877 `CX q42 q16` |
| q61 | 27 | 0 | 0 | op16886 `CX q61 q16` |
| q49 | 53 | 2 | 0 | op16761 `CX q49 q46` |
| q46 | 68 | 1 | 0 | op16750 `CX q14 q46` |

  "该点之前把某条线的值消费掉"，而这些点在链中间，前后都被同一批阻塞门夹住。

因此交换路线把可覆盖峰值从 2,103 提到 2,157（+2.1%），但**没有改变"没有 61Q 候选"的结论**；
代价 9 C 低于预算，缺的是那 393 个指令的"让某条线死掉"的机制。

## 8. 非线性重建路线（2026-11-07 续）

第 7 节与 `20261107_peak_rank` 已把**线性/奇偶**路线封死：1,175 个峰值指令上 62 个活跃值
GF(2) 秩为 62（首个/末个 16731/24364），`[16731,18483)` 整段满秩。
本节测试**非线性**重建：某条线的值能不能用其余 61 条线的廉价非线性函数写出来。

### 8.1 判定方法（精确，全域）

新增 [nonlinear_rebuild.py](nonlinear_rebuild.py)。核心是把"用 AND 重建"化成一个线性代数问题：

若 `w = L1 & L2`（Li 是其余 61 条线的仿射型，即某个子集的 XOR，可用 CX/X 免费构造），
则两个因子都必须在 `w=1` 的所有 x 上等于 1。于是定义**覆盖集**

```
A(w) = { L 仿射 : supp(V_w) ⊆ supp(L) }  \  {恒 0, 恒 1}
```

`A(w)` 用一次 GF(2) 消元在**全部 3,133,452 个合法 x** 上精确求出：
- `c=0` 族：解 `⊕ a_v (V_v & V_w) = V_w`（特解 + 零空间）；
- `c=1` 族：零空间上的 `⊕ a_v V_v = 0`，再整体取补。

`A(w)` 的大小是 `2^(零空间维数)`。得到 `A(w)` 后：
- 单积：`L1 & L2 == V_w`，`L1,L2 ∈ A(w)`；
- 三次单项：`L1 & L2 & L3 == V_w`；
- 秩 2 二次型：`(L1&L2) ⊕ (L3&L4) == V_w`。
全部是全域等式，不是抽样。`HMR` 分支用 `simulate(..., branch_seed)` 切换。

### 8.2 代表指令上的结果：确实存在 1-CCX 重建

| op | 指令 | 有非平凡仿射覆盖的线 | 单积（1 CCX） |
|---|---|---|---:|
| 16750 | `CX q14 q46` | 8 / 62 | **4**：q20, q25, q26, q27 |
| 16887 | `CCX q15 q16 q20` | 7 / 62 | **2**：q25, q27 |
| 18483 | `CX q52 q14` | 4 / 62 | 0 |

例：op16750 处

```
q25 = XOR[18,24,28,29,30,32,33,34,35,43,44,45,47,48,49,52,53,55,56,59,61]
    & XOR[14,15,30,31,32,33,34,35,37,40,42,43,47,54,56,58,60,61]      (21 项 & 18 项)
q20 = XOR[14,15,17,27,29,30,31,32,34,35,36,38,41,43,46,50,51,54,56,58,59,60,61]
    & XOR[14,17,18,21,30,31,34,35,37,38,40,47,49,51,53,54,57,58,61]    (23 项 & 19 项)
q26 = 22 项 & 18 项      q27 = 18 项 & 20 项
```

**三分支验证**（`verify_products.py`，全域）：同一组因子在 all-zero、随机分支 1、随机分支 2
上都满足 `L1 & L2 == V_w`，即这是电路真实计算的结构，不是某一分支的巧合。
代价：**1 个 CCX**（两个因子用 CX 链免费构造；需要 2 个临时线，见 8.4）。

这与第 7 节的观察一致：这些"累加器"在链上就是一个个 20 项线性型的乘积。

### 8.5 结论

- **非线性重建没有解决 61Q**：在阻塞区间的出口处，候选线的值不是任何仿射型族的 AND
  （覆盖集为空），不存在廉价（甚至中等）的乘积型重建。
- 唯一的结构性发现是代表指令处确实存在 1-CCX 的 20 项线性型乘积（q20/q25/q26/q27），
  三分支全域验证通过；但这些线在阻塞区间内被触碰，不能整段停放。
- 最小二次秩：对被搜索的族，q61@16886 是唯一还有覆盖的候选，k ≥ 3；
  其余候选的单项式族为空，秩无定义（不是"很大"，而是根本没有乘积表示）。
- 因此仍**没有 61Q 候选**；保持 62Q 是已知最便宜的选择（97,700.776777236）。

## 9. 下一步的明确入口（如果继续）

1. 若要把 61Q 做实：先给 op24922 处 q23 的值找一个 ≤16 门的全域表达式，或证明它必须
   重放 `[16189,16731)` 的哪一段；这是唯一挡住 2,157/2,550 覆盖的缺口之一（393 ops 中最大的一块）。
2. 交换路线已封口：`[16731,18483)` 的 13 条阻塞门（`CX q14 q46` 等）是线性型链的链节，
   要让源线通过，必须改成"另一条链"而不是重排；这属于改表示，不是改顺序。
   剩余 393 个指令里还有 `[15691,15724)`（q28 旋转/纠相级联）和 12 个单点块，
   同样需要新的表示，而不是更多重排。
3. 若不接受重建：转向"改表示"（例如把 q23 在 `[16199,24922]` 携带的那 1 bit 换成
   某个能在 op24922 用两三条线算出的量），而不是继续在现有线上做值保持改写。
4. 任何 61Q 候选都必须先补：61 寄存器区间着色、插入 SWAP/HMR 后的相位修复
   （`CZ 因子 if m`）、以及全域/多分支的等价性检查，再手动跑官方验证。
