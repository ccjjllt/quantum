## 1. 口径

官方计费：`C = E[CCX+CCZ+CSWAP] + E[T]/4 + E[一般旋转]·(0.56·log2(1/eps)+5.3)/4`，
`score = Q·C`。基线完整官方本地结果（沿用 q61 记录，本轮不重跑）：
62Q，`C = 1,575.818980278`，`score = 97,700.776777236`，200,540,928 shots，PASS。

61Q 打平条件：

```
61 · (C + ΔC) < 62 · C   =>   ΔC < C/61 = 25.833098 C
```

本文的 `r` 是**乘积数**，每个乘积用一个 `CCX` 完成，所以 `r` 也是新增的付费门数。
它与对称二次型矩阵的秩 `2r` 相差一个因子 2；用户给出的“rank 10/14 → 5/7 CCX”正是这个约定。

## 2. 六个正结果的复现与全域验证

拟合方法（`quadfit.py`）：在 4096 个合法 x 上，把目标线 `w` 表示为其余 61 条线值的

```
w = c ⊕ Σ a_i v_i ⊕ Σ_{i<j} b_ij v_i v_j
```

共 1 + 61 + 1830 = 1892 个单项式特征，用 GF(2) 高斯消元求解。特征顺序是
常数、线性、二次；这个顺序复现了用户给出的六个单项式数（138/131/119/130/129/128）
和秩（10/14 → 5/7 个乘积）。

二次部分用交错极形式 `B` 的辛 Gram–Schmidt 分解为 `r` 个线性型乘积
（`decompose.py`）：

```
w = A(v) ⊕ Σ_{j=1..r} L_j(v) · M_j(v)
```

`A` 是仿射修正，`L_j, M_j` 是仿射线性型。分解后用 4096 x 样本回代，六个全部相等。

**乘积的物理 gadget。** 设当前要重建的目标线为 w（已用 `R` 复位为 0），另有一个干净累加器 c
（另一个被停车的线，或非峰值点的空余下标）和一条可借用的活线 b。对每个乘积 `L·M`，
取 `b` 为 `M` 中系数为 1 的一条线，写 `M = b ⊕ M'`：

```
w ^= L                 # CX，免费
b ^= M'                # CX，免费；此时 b = M
CCX w b c              # 唯一付费门；c ^= L·M
b ^= M'                # 还原 b
w ^= L                 # 还原 w = 0
```

全部乘积累加完后对 c 施加仿射修正（CX/X，免费），最后 `SWAP c w`（免费）把结果放回 w，
c 回到 0。所以 r 个乘积确实只需要 **r 个 CCX**，其余是免费的 CX/X/SWAP。
借用线 b 在每个乘积后被精确还原；逐乘积的乘积因子可以包含 b 的初值，上面的顺序先算 L、
再改 b、最后先还原 b 再反算 w，因此 L 含 b 也成立。

**分支问题。** q61 的 `nonlinear_rebuild.simulate` 和 `multibranch.run_branch`
把所有条件 `CX/CCX/X` 无条件执行，这不是真实分支。本轮新增 `branchsim.py`：
跟踪 HMR 写入的经典位（同名位会被多次改写），条件门只在条件栈全为 1 的 x 上执行；
HMR 仍按“随机硬币 + 复位”处理。用这个模拟器重新拟合，六个单项式数和秩**完全不变**，
说明它们不是全 0 分支的偶然产物。

全域验证（`verify_full.py`）：对全部 3,133,452 个合法 x，分别在全 0 分支和两个随机分支
（seed 101、202）上计算同一组系数的多项式，与目标线值逐位比较。六个全部三个分支 PASS。

## 4. 精确最小覆盖：53 C

免费停车覆盖 1,918/2,550 个峰值指令；q61 的 sound 交换覆盖（`commute_v4.json` 的 8 个
`chosen` 块，整块 `range(a,b)`）覆盖 114 个峰值指令，其中 **54 个**是免费停车未覆盖的新指令。
两者并集 **1,972/2,550**，剩余 **578 个缺失指令，分布在 33 个 run**。
每个候选的覆盖集是该 gap 内峰值指令的一个连续区间，所以最小代价覆盖可以精确地用区间 DP 求

## 5. 全域验证的实际范围

`verify_full.py` 验证了 29 个不同的 (wire, gap)：最小覆盖的 11 个、全部 16 个 rank-1 选项、
以及六个用户正结果（有重叠），共 87 次检查（29×3 分支）：

- **84/87 PASS**；
- 唯一失败的是 q28 gap `[15299,15301]`（op15301，9 个单项式，rank 1），
  在三个分支上全 FAIL。它是 4096 x 样本上的伪拟合，**未进入最小覆盖**；
- 最小覆盖的 11 个选项全部 3/3 PASS，包括新加入的 q59 `[17935,18191)`。

因此 53 C 的解是一个**已验证可用**的覆盖（每个重建关系都在全合法域和两个随机分支上精确成立），
只是成本远超 61Q 预算。未对全部 1,289 个最终可用选项（1,290 个样本可用，1 个全域失败被剔除）
做全域名验证；样本拟合只用于定价，
最终结论所依赖的 11 个重建已全部全域通过。

不需要对全部 1,352 个候选做全域名验证来支撑负结论：53 C 的解只使用已验证的 11 个选项；
一个未验证选项若在全域失败，只会被删除（抬高最小值），不会降低它。
唯一能降低最小值的是同一个函数存在**更低秩**的表示，这由第 8 节的核空间下降单独检查。

## 6. 为什么没有生成 KMB、没有跑官方验证

用户要求只有在精确期望新增 `C < 25.8331` 且覆盖全部 2,550 个值活跃 62 峰值时才生成 KMB。
本轮最小覆盖是 53 C，乐观下界 50 C，均不满足；所以：

- 没有生成 61Q KMB；
- 没有运行 `verify_submission_invsqrt.py`；
- 没有修改基线、官方数据或验证器；
- 没有提交 Kaggle、没有推送代码。

真正的 KMB 还需要全局寄存器分配/别名：每个被停车线的值要在 gap 出口重建，前后的使用要一致，
释放的下标要被复用，且重建 gadget 需要一个干净的累加器下标（另一个被停车的线，或非峰值点的空余下标）。
本轮没有走到那一步，因为成本条件已经不成立。

## 8. 边界与未决问题

- 4096 x 的二次拟合只用于**筛选和定价**；最终 11 个重建在全域和两个随机分支上验证。
  没有证明这些 rank 是数学最小值：核空间下降没有降低它们，但一般性的 rank-2/3/4 表示搜索
  没有做完。如果中段/后段的 10 个 rank≥5 选项中有足够多能降到 rank≤2，结论可能改变；
  这是本路线唯一未关闭的口子。
- 免费停车覆盖 1,918 个指令沿用 q61 的模型（`span_test` 512 x 采样线性命中），
  免费交换覆盖沿用 q61 的 `commute_v4` sound 块。
  若其中某些“免费”选项实际不成立，缺失集会变大，最小成本只会**更高**；
  不会把 53 C 降到预算内。反过来，本轮没有发现新的 rank-0 选项（1,352 个候选中 0 个）。
- 条件感知模拟修正了 q61 的条件门问题；全 0 分支现在是真的“所有 HMR 结果为 0”，
  而不是“所有条件门都执行”。六个正结果在修正后不变，这是本轮对 q61 结论的加强。
- 没有跑官方验证器：没有出现成本达标的候选。53 C 的覆盖即使做成 KMB，
  `61·(1575.818980278+53) ≈ 99,357.958 > 97,700.776777236`，不会改善分数。
- 未检查“多个重建共享乘积”或“在非出口点重建”的联合优化；本轮按用户指定的
  (wire, gap, 出口 op) 独立定价。共享优化可能降低常数，但要把 53 C 降到 25.83 C
  需要减少 27 C 以上，量级上不现实。
