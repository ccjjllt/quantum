# invsqrt：62 峰值处活跃值的线性秩（61Q 重综合的第一道门槛）

日期：2026-11-07。基线只读：`artifacts/20261106_syed_v9/invsqrt/syed_v9_nofallback.kmb`
（62Q，官方本地 PASS，score 97,700.776777236，C=1,575.818980278）。
本轮检查的是用户指定的 61Q/60Q 重综合方向：在 `[16731,18483)` 的线性型累加链上，
能否用输出线/经典奇偶表示少用一个量子位。

## 方法

脚本 [peak_rank.py](peak_rank.py)：

1. 读取 q61 的**值活跃性**区间（一次写入到下一次写入前最后一次读取），
   逐条指令统计活跃值数；取所有 62 活跃值的峰值指令，共 **2,550 条**。
2. 在 20,000 个随机 x、随机 HMR 分支上模拟到每个峰值指令，
   对当时活跃的 62 条线做 GF(2) 秩。
3. 秩 62 表示 62 个活跃值线性无关：不存在任何 `CX` 线性重编码或
   经典奇偶（也是 GF(2) 线性）能把其中一条线消掉而不丢失信息。
   秩 ≤61 表示存在一个局部线性关系，可以尝试重编码。

样本上秩 62 是一个**全域见证**：如果这些函数在全部合法 x 上线性相关，
它们在 20,000 个样本上也必须相关；因此样本上的满秩否定了全域线性关系。

## 结果

`artifacts/20261107_peak_rank/peak_rank.json`：

| 峰值活跃秩 | 指令数 |
|---:|---:|
| 62 | **1,175** |
| 61 | 343 |
| 60 | 86 |
| 58 | 920 |
| 57 | 26 |
| 合计 | 2,550 |

- 满秩 62 的峰值从 **op16731 到 op24364**；`[16731,18483)` 的阻塞区
  正是满秩的。
- 秩 ≤61 的峰值共 1,375 条，主要落在旋转簇/暂停覆盖区；q61 的
  暂停+交换方案已覆盖这些区域的大部分（2,157/2,550），
  剩余 393 条与满秩峰值重合。

## 结论

- 在 `[16731,18483)` 的 62 峰值上，活跃的 62 个值线性无关；
  **输出线重排、经典奇偶、免费 CX 线性编码都不能少一个量子位**。
- 因此用户指定的“用输出线/经典奇偶重综合这条线性型累加链”在这段
  峰值上被线性秩否决；要降到 61Q 必须使用**非线性状态编码**
  （或改变算法/调度），而不是线性/奇偶表示。
- 这解释了 q61 的 13 条“累加器当控制”阻塞门：它们把线性型链锁在
  满秩状态，局部交换/重排无法绕过。
- 本轮没有生成 61Q/60Q 候选，没有运行官方验证；基线不变。
