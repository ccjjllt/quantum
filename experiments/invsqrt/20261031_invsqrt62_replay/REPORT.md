# 62Q invsqrt 重放、混合生成与 Horner 复核

日期 2026-11-01。分支 `invsqrt-generator-rebuild`，与 `origin/invsqrt-generator-rebuild` 对齐，工作区有未提交修改。这次没有新的提交、推送或 Kaggle 提交。官方验证器未改。已删除的 87Q 目录没有恢复，它的表和 44 个角度没有读入。

## 假设

公开 62Q 电路就是 Ahmed 相对 yoyobar 的一次历史缓存。尾部在清掉中间值之后又重算了一批 CCX。若能证明某一处是「产生 y、清除、测量、再算同一个 y」，并且活前沿只有 1–2 个非线性输出，保留 y 可能降低 `Q × C`。Horner 段里，T 宽 19、C2 宽 8 是待检验的整数寄存器，不能用「两个 delta 下恰好有 19/8 条地址常量线」来判定。

## 已证实

Ahmed 规范 KMB 的 SHA-256 是 `6dbb98b34c3b16f1c4e019350c10d42259a6faa97e464c9b7c9390f877f392f4`。逆补丁得到 yoyobar `a568bc79348165bad5be2349960d200300c5639ffd2142aca6d548e764a399d9`，再打回补丁仍是 Ahmed。静态 Toffoli-like：Ahmed 1501，yoyobar 1502。

补丁本身：yoyobar 的 op 46718 是 `CSWAP q16 q2 q23`，op 46796 是 `CSWAP q19 q6 q41`。Ahmed 在前一个 CSWAP 两侧各插入 `CX q2 q60`，并把后一个 CSWAP 换成 q60 上的 10 条缓存操作。少一个无条件 Toffoli。

宏观五段仍保留。测量条件修正算进所属块后，语义边界是：`Hphase 15244:16127`，`A 16127:20738`，`B 20738:25630`，`Lphase 25630:28726`，`inverse_B 28726:32226`，`inverse_A 32226:43870`，`unlookup 43870:46706`，`tail 46706:47201`。

`generate62.py` 是托盘重放加局部语义替换的混合生成器，不是完整独立生成器。局部语义只有三段：op `3:23` 的输入补码、41 条一般旋转，以及 Ahmed 历史缓存。A（`16127:20738`）和 B（`20738:25630`）整段仍是 replay。Lphase（`25630:28726`）里只有 26 条一般旋转是 semantic，其余行仍从 `yoyobar_tray.kmx` 复制。这三段区间互不重叠。`gate_level_replay_complete` 只表示托盘重放及哈希一致。公开 oracle KMB 不在生成输入的 `opened_paths` 里；provenance 另记它的 SHA-256 和字节数。kickmix 发行版是 1.0.0。

定向差分在种子 101、202、303 上覆盖 uniform、boundary、256 个地址、`x161`、`x888` 和 137 个进位边界。真实输入与 256-shot padding 分开计数。这 18 组的真实输入：x 错误 0，scratch 按 `read_across_shots(scratch).any(axis=1)` 的脏计数 0，64-bit 相位不一致 0。Toffoli-like 字段是整批累计值，含 padding，不是单个 x 的成本。

一般旋转 41 个。高字 15 个都在 `q28`，低字 26 个分布在 `q50`、`q41`、`q40` 和 `q28`。`F0=28`、`G0=1`、`S=20` 的读法是相位窗口：`R0=F0-G0=27`，`nHf=F0-1-S=7`，`offH=S-G0=19`，高字角度贴近 `2^(46+k)`。这次对全部合法 x、种子 101、每 x 一次复核了该窗口：`s<=7` 的 3,133,389 个 x 上，窗口外为 0、常数位为 1，失败 0；`s>7` 的 63 个 x（`x=1..63`）落在 15 个高字槽之外，窗口约束不适用。这仍不是官方 PASS。

`LB=18` 已否定。反例是 `x=128`、`s=7`，低字下标 25 为 op 25870 的 `q28`，该位为 1，超过 `s+15=22`。`model_check.json` 里 `LB` 标为 rejected，不再当作活的低字宽度。

`model62.py` 对全部 `x=1…3133452`、种子 101、每 x 一次做了计算基检查。x 恢复失败 0，scratch 失败 0，相位容差失败 0。最小绝对余量 58597850 个 `2^-64` 圈。最紧的相对误差在 `x=161`。官方验证未运行，0 shots。

## Horner 的 T 与 C2

切点写在 `horner_cuts.json`。A、B 内部按 CX 扇出和贴近 CCX 的 HMR/R 取了 40 个深度为 0 的切点，并保留 Lphase 前的 op 25630。每个切点有 62 线快照、最后写 op、直接值来源、测量依赖、条件深度，以及只由无条件 SWAP 更新的逻辑标号。CSWAP 一律记为未解析屏障，没有当成静态交换。样本在固定 `(address,s)=(0,0)` 上包含 delta 0、1、单比特、进位边界和最大值，并另有 address/s 对照。

整数寄存器只从变化类和值来源里找连续段，不把更宽的扇出切成 8 或 19。宽度 19 在物理变化类、物理变化类加值来源、以及 SWAP 逻辑标号上的候选都是空列表。宽度 8 且值来源一致的有四条：op 21091、21156、21172 上的 `q4..q11`，最后写都是 `X`/`NOT`，变化类是只随 delta 变；以及 op 21091 上的 `q32..q39`，最后写都是 `CX`/`XOR q13`，变化类是只随 address 变。`q4..q11` 的整数读法是「线 q 等于 delta 的第 q 位」。定向样本和全部 3,133,452 个 x 上，这三处切点的不一致数都是 0。它不是 C2，因为它随 delta 变；也不是 T，因为宽度是 8。`q32..q39` 按 address-only 的 8 位字来读。定向样本里同一 address 的字不变，不同 address 的字会变。全域对照里它在同一 address 内改变：`x=3` 与更早的 address 0 相比，字从 26 变成 31。这样的冲突有 1,048,575 个。Horner 递推没有套到任何寄存器上，因为没有宽度 19 的 T。41 个旋转控制位没有重建。`FT=19` 和 `F2=8` 仍未确认。A、B、Lphase 没有离开托盘。

## 保留中间结果

`retain62.py` 的收益排名同时要求：frontier 为 1 或 2、source/copy 值签名相等、copy 前目标为零、保留值存活期无覆盖、未跨越未解释的 HMR/R。签名、条件环境、零态和存活期都写在 `retention_candidates.json`。没有任何一条同时满足，所以 `best` 是 null，`decision` 是 `no_eligible_candidate`。修正前那个「省 4 门」的条目签名不相等，不是有效候选；修正前没有可靠的最佳节省估计。

同一规则数到 133 个重复 CCX，逐项 op 和排除原因都在 `repeated_ccx_ops`。历史 141 没有留下逐项清单，记录是「历史数字不可复现」，不用边界解释这 8 个数。`no_eligible_candidate` 只针对窗口 `15583:36941` 和上述规则，不是保留路线的全局否定。没有 `retain_r1.kmb`，也没有第二个保留实验。

## 下一步

保留路线先停在这次筛选。再恢复之前，需要双侧语义和清理证明、净节省超过 25.842 或 50.877，以及定向差分和全 x 局部检查。只有那时才手动跑 `scripts/manual_verify.py` 的 200,540,928-shot 官方验证。

Horner 下一步是换一种值来源，而不是把未确认的 A/B/Lphase 迁出托盘。完整语义生成器还要等全部 replay 区间消失，并且能在不含公开 oracle 和 tray 的输入上重建。
