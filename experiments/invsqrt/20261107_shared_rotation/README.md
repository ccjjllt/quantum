# invsqrt：共享多输出旋转 gadget / 不同相位生产顺序

日期：2026-11-07。工作区 `.worktree/invsqrt`，分支 `codex/invsqrt-research`。
基线只读：`artifacts/20261106_syed_v9/invsqrt/syed_v9_nofallback.kmb`
（62Q，官方本地 PASS，`C=1,575.818980278`，`score=97,700.776777236`，41 个 fine rotation）。

本轮问题：是否存在一种**共享多输出旋转 gadget + 不同归一化/相位生产顺序**的架构，
把两个旋转簇的 `153C` 付费逻辑或 `294.840824C` 旋转合成压低，从而在 62Q 上严格
改善 score，或在 61Q 上只用 `<25.8331C` 的新增成本？

## 0. 结论

**不存在。本轮没有候选 KMB，没有运行官方验证器，没有 Kaggle 成绩，基线文件未修改。**

三条腿分别被不同类型的证据关闭：

1. **B（多输出相位累加器）不是成本问题，是数学不成立。** 相位在实数上相加，
   而累加器用 XOR 组合相位 tap：两个同时为 1 的 tap 在掩码里相消而不是相加。
   四种“共享测量”的写法在全域 `x=1..3,133,452` 上分别有
   `3,133,452 / 3,133,451 / 3,133,448 / 1,048,575` 个 x 超出官方容差，
   最大偏差 `0.1667` turn，最坏 `|err|/tol` 达 `3.69e9` 倍。
   这不是排版误差，是恒等式错误。
2. **A（共享单项式基）相位精确，但真实成本太高。** 41 个掩码在块起点线值上的
   精确 ANF 有 `1,461` 个项实例、`437` 个不同单项式（`408` 个非线性）。
   每个非线性单项式必须自己占一个 AND 输出：**下界 `408` 个 CCX**，
   链式实现 `1,086` 个 CCX，而它要替换的旋转簇付费逻辑只有 `153C`
   （`2.67×` / `7.10×`）。62Q 总账 `score ≥ 122,996.8`，比基线差 `+25,296`。
3. **现有相位生产里的真实单项式共享只有 3 个 tap，且每个只用 2 次。**
   共享一个 2 次的 tap 需要“算一次 + 撤销一次”= 2 个门，与直接算 2 次完全相同
   **净收益 0C**。唯一能省的 3C 需要一个可丢弃（可 HMR）的干净辅助线，
   实测在 op 15315 处没有任何线恒为 0、也没有两条线携带同一值，
   每个未触碰线的下一个操作都是读它或 XOR 写它 → 必须显式撤销 → 0C。

因此 62Q 最好情况是**与基线完全相同**（`Δscore = 0`，不满足严格 `<`）；
61Q 需要先付当前门序列的 `53C` 下界；63Q 需要净省 `25.013C`，实测最大是 0C。

## 2. 两个旋转簇的 153C 到底由什么组成（实测）

基线**不是**“41 个独立 gadget”。每个旋转簇共用一个累加器
（block 1 是 q28、block 2 是 q50 → q41 → q40 → q28），每个旋转只把
它自己的 3–5 个 tap XOR 进累加器，`Z_POW` 后 `HMR` 复位。所谓
“41 separate gadgets”在基线上已经不存在，这本身就是共享累加器的设计。

`tap_decompose.py` 在全部 `x=1..3,133,452` 上逐门追踪，把每个旋转的掩码精确分解为
“上一次复位以来写进累加器的增量”的 XOR；**41/41 与 `masks_full.json` 逐位相同**。

| 量 | 实测 |
|---|---:|
| 累加器写入（tap use）总数 | **179** |
| 其中不同函数个数 | **176** |
| 重复次数直方图 | `{1: 173, 2: 3}`（最大重数 2） |
| 3 个重复 tap | `q21&q41`(rot 4,12)、`q21&q25`(5,13)、`q21&q26`(6,14) |
| 付费 tap use（CCX/CSWAP） | **147**（其中不同函数 144） |
| 可用“静态乘积”形式表达的 use | **97** |
| 增量含累加器自身值的条件交换（mux）use | **82** |
| 静态乘积的不同函数 | **62**，其中被共享的 **3** 个 |

按窗口（半开区间，零基 KMX 指令）：

| 窗口 | 付费门 | tap use（付费） | 旋转 | HMR |
|---|---:|---:|---:|---:|
| `[15278,15617)` | **62** = 52 tap + 10 非 tap | 62（52） | 15 | 16 |
| `[25408,25649)` | **91** = 全部 tap | 91 + 4 个来自窗口前 | 26 | 28 |
| 合计 | **153** | 147 | 41 | 44 |

窗口 1 的 10 个非 tap 付费门：`CSWAP q21 q50 q1`(15282)、`CSWAP q23 q1 q41`(15313)、
`CSWAP q23 q50 q41`(15352)、5 个 `CCX q32 qX q1`(15363/15413/15466/15517/15562)、
以及**在最后一个 block-1 旋转（op 15607）之后**的 `CSWAP q20 q28 q3`(15610)、
`CSWAP q27 q28 q0`(15611)。后两条服务于不存在的旋转，但仍计入 2C；
它们不是空操作（实测 q28 在该点 popcount 63/62，q20=246,723、q3=1,435,655），
删除会改变后续算术，属于另一类（逐门删除）实验，本轮不动。

**82/179 的 tap 是“条件替换”而不是 XOR 单项式**：`CSWAP c acc x` 的增量是
`(acc⊕x)&c`，含累加器自身。只有当 `acc&c ≡ 0` 时才退化成静态乘积 `x&c`
（这就是 97 个“静态” use）。这直接说明“把累加器留着不测、继续 XOR 累加”
不能用 XOR 线性代数描述。

## 3. A：共享单项式基（用真实掩码测量，不是通用估计）

41 个掩码可以精确写成块起点 62 条线值的 Boolean 表达式
（`artifacts/20261107_streaming/symbolic_masks.json`，41/41 全域验证）。
在这组线性型上取精确 ANF：

| 量 | 实测 |
|---|---:|
| ANF 项实例 | 1,461 |
| 不同单项式 | **437**（常数 1、线性 28、非线性 **408**） |
| 最高次数 | 8（按次数分布 `0:1, 1:28, 2:77, 3:106, 4:127, 5:79, 6:14, 7:4, 8:1`） |
| 每个单项式算一次：CCX 下界 | **≥408** |
| 链式实现（能用 (deg−1) 子单项式就复用） | **1,086** CCX |
| 共享带来的节省（相对 1,461 个项各算一次） | 1,013 个 `(deg−1)` |
| 对比：旋转簇付费逻辑 | **153C** |

即：共享确实是真实的（`2,099 → 1,086`，约 `1.93×`），但绝对值是
`153C` 的 `2.67×`（下界）到 `7.10×`（链式），更不用说 437 个单项式在 62Q 下
不可能同时存活，流式实现还要额外的 ancilla 与撤销。

**这一条不是“再算一遍 ANF”**：`20261107_direction_research` 里的 ANF 结论是
“直接对 x 位做 ANF 不可行”；这里的对象是**块起点线值**上的精确 ANF，
并且用它给出共享单项式架构的**具体门数下界**，与基线已有的 mux 表示直接比较。

## 4. B：多输出相位累加器（全域相位检查失败）

四种“几个 Z_POW 共用一个累加器、共享 CSWAP/HMR/cleanup”的写法（两个块的
“同一值多次 Z_POW”、XOR 前缀累加、tap 系数转置），全部在
`x=1..3,133,452` 上按官方整数 target/tolerance 检查：

| 变体 | 机制 | n_rot | 超容差 x 数 | 最大偏差 (turn) | 最坏 \|err\|/tol |
|---|---|---:|---:|---:|---:|
| B1 block1 | 15 个 Z_POW 作用于同一个不变值（角度相加成一个旋转） | 27 | **3,133,452** | 1.245e-1 | **3.69e9** |
| B1 block2 | 同上，26 个旋转 | 16 | **3,133,451** | 9.766e-4 | **2.90e7** |
| B2 prefix | 保留累加器，XOR 累入更多 tap，角度取 `θ_i−θ_{i+1}` | 41 | **3,133,448** | 1.667e-1 | **3.33e7** |
| B3 transpose | 每个不同 tap 一个旋转，系数 = 用过它的角度之和 | 176 | **1,048,575** | 1.579e-1 | **2.12e7** |

原因是同一个：`Z_POW` 的相位在实数上相加，而累加器用 XOR 组合掩码。
若两个 tap 在同一个 x 上同时为 1，它们的 XOR 是 0（相消），而相位需要相加。
B1 更直接：同一累加器值上的多个 `Z_POW` 只能合成一个角度，
所以“共享一次测量”等价于“把几个掩码合并成一个”，而 41 个掩码 GF(2) 秩 41、
两两不同，合并必然改变相位。

**因此 B 唯一合法的用法是把完全相同的掩码合并**——实测 41 个掩码互不相同（秩 41），
没有可合并项。作为参照：即使 B3 的相位代数成立，176 个旋转的合成成本是
`1,317.448C`（`+1,022.608C`），本身也已远超全部预算。

## 5. C：不同归一化/相位生产顺序（相位精确，零收益）

41 个 `Z_POW` 都是对角门、互相可交换，所以任意重排**相位逐位不变**：
`C_reordered_phase_production` 在全部 3,133,452 个 x 上与基线完全相同
（最大偏差 0，最坏比 0.9993237694056958 @161）。

但重排本身既不增删门也不改旋转数：`ΔC = 0`。要让重排产生收益，必须让某个
掩码在另一个时刻可用，而实测（`20261107_streaming` §3、§4）：

- 41 个掩码的支撑并集是 block 1 的 **45** 个线值 / block 2 的 **27** 个，
  且只有 `2/15` 与 `0/26` 个掩码的支撑是生产顺序的前缀；
- 每个掩码只在它自己的 `Z_POW` 点作为某条线的值存在（0/41 等于任何其他线值）；
- 即使删掉整个旋转机器的全部读取，q61 值活跃性峰值仍是 62。

唯一能让重排改变账本的是把 3 个重复 tap 的旋转相邻化，从而顺序复用一条脏辅助线：
每个 tap 仍是“算一次 + 撤销一次”=2 个门，与直接算 2 次相同 → **0C**。

边界注记（不是本轮候选）：41 个角度里有 8 对落在同一 dyadic 权重
（`2^-10..2^-17`），但它们的角度**并不相等**：最大 `|θ_a−θ_b|/2 = 531.8` 倍基线 margin
（`phase_check.json` 的 `near_equal_angle_pairs`）。要合并这些成对旋转必须整组重拟合角度，
且需要一个掩码在另一个旋转的时刻仍可用——这正是上面被否掉的条件；
该方向属于已关闭的 33 旋转数值族，本轮不重跑。

## 7. 缺口论证（本架构的下界）

对本架构（共享多输出旋转 gadget、任意归一化/相位生产顺序）给出：

1. **相位层**：任何“多个 Z_POW 共用一个会变化的累加器”的写法都不是恒等式
   （§4，全域反例）。合法用法只剩同一累加器值的角度相加，
   而 41 个掩码 GF(2) 秩 41、互不相同，无法合并。→ 旋转数不能靠 B 降低。
2. **单项式层**：41 个掩码的精确 ANF 需要 `408` 个非线性单项式，
   每个必须占一个 AND 输出 → `≥408` 个 CCX，是它替换的旋转簇
   `153C` 的 `2.67×`。这是**共享之后**的下界（每个单项式只算一次）。
   → 62Q 的 score 下界 `≥122,996.78`，缺口 `+25,296.00`。
3. **tap 层**：真实生产调度里 179 个 tap use 只有 176 个不同函数，最大重数 2。
   k=2 的共享成本 = 2 个门（算 + 撤销）= 直接算 2 次 → `0C`。
   能省的 `3C` 上界需要可丢弃辅助线；实测 op 15315/15324/15333 处
   **没有 popcount 0 的线**，也没有两条线同值，且每个未触碰线的下一个操作
   都读它或 XOR 写它（`ancilla_check.json`）→ 必须显式撤销 → `0C`。
4. **顺序层**：重排相位精确但 `ΔC=0`（§5）；把旋转前移的必要条件是掩码的支撑值同时存在，
   实测最多提前 364/258 条指令且不释放任何峰值（`20261107_streaming`）。

合起来：**本架构在 62Q 的最大净收益是 0C，在 63Q 是 0C（回本需 25.013C），
在 61Q 需要先付 53C**。三条都不进入任何预算。

## 8. 计数 vs 估计

**精确计数（全域或逐门普查）**

- 179 个 tap use / 176 个不同函数 / 重数直方图 `{1:173,2:3}`；147 个付费 use；
  97 个静态乘积形式、82 个状态相关 mux；62 个不同静态乘积、3 个被共享。
- 两个窗口的付费门 `62 + 91 = 153`，以及窗口 1 的 10 个非 tap 付费门（逐门列出）。
- 41 个掩码的 ANF：1,461 个项实例、437 个不同单项式、408 个非线性、最高 8 次。
- 基线 margin `58,597,850` units、最坏比 `0.9993237694056958 @161`；
  B1/B2/B3 的超容差 x 数与最大偏差；C 的逐位相同。
- 旋转合成 C 与 n_rot 的关系（官方 `0.56·log2(1/eps)+5.3` 公式）。

**下界 / 估计**

- 单项式架构 `≥408 CCX` 是下界（每个非线性单项式一个 AND 输出，不含 ancilla 与撤销）；
  1,086 是“尽量复用 (deg−1) 子单项式”的具体实现值。
- 干净辅助线 `−3C` 只是上界，已证明 62Q 不可实现。
- 61Q 的 `53C` 来自既有记录 `20261107_61q_lower_bound`，不是本轮新测。

**没有做**

- 没有生成任何 KMB（账面 `ΔC ≥ 0`，不满足“先全域数值通过且 `ΔC<25.8331`”的进入条件）。

## 10. 范围与限制

- 本轮的否定结论覆盖的是**本轮定义的架构族**：共享单项式基（自由 XOR + 付费 AND）、
  多输出相位累加器（共享测量）、以及保持 41 个掩码的重排。
  它不证明任意新算法不可能；一个避免在峰值处物化相位、且不用 XOR 累加器的新表示
  仍然可能（但那需要另一套构造）。
- “B 的相位代数失败”是全域反例（逐个 x 的整数比较），不是抽样。
- “A 的单项式成本”以块起点线值的精确 ANF 为基；换一组线性型可能得到不同的单项式集合，
  但 `408` 这个下界只依赖“每个非线性单项式必须占一个 AND 输出”，
  而单项式个数来自 41 个掩码的**精确** ANF，是这组线性型上的确切值。
- 干净辅助线的不可实现性只在三个重复 tap 的实际 span 上检查；
  若将来重排使 span 变化或出现新的重数 ≥3 的 tap，结论需要重算。
- 两个窗口的 153C 是静态计数且全部无条件，与官方 `toffoli_count` 一致到抽样噪声；
  分阶段成本来自 3×16,384 抽样（`20261106_direction_research`）。
