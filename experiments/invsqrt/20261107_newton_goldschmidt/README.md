## 2. 算法规格

### 2.1 归一化

```
e = floor(log2 x) ∈ [0,21]        (22-bit LOD，后缀 OR 链，实测 22C)
k = e >> 1 ∈ [0,10]
R = x << (21 - 2k) ∈ [2^21, 2^23) ,   m = R / 2^21 ∈ [1,4)
```

`m` 的跨度是 3（不是 4），所以 dyadic 地址切片需要 `2^sh ≥ 3·2^21/E`：

| 表项数 E | sh | 段宽（m 单位） | 可达地址数 | QROM 实测 |
|---:|---:|---:|---:|---:|
| 256 | 15 | 2^-6 | 192 / 256 | **279C** |
| 1024 | 13 | 2^-8 | 768 / 1024 | **1,078C** |

1024 项单独就把 694.84C 预算吃掉 1.55 倍，所以主设计用 256 项。
种子取段中点 `m_mid`：相对误差 ≤ 2^-8（256 项）/ 2^-10（1024 项），即题面的 8-12 bit。

### 2.2 Newton 与 Goldschmidt

Newton（对倒数平方根就是 `y(3-m y²)/2`）：

```
u = m*y_k^2 ;   y_{k+1} = 1.5 y_k - 0.5 y_k u
```

这里刻意写成**无符号**形式：`u ∈ [1-2^-7, 1+2^-7]` 是正数，`1.5 y_0` 是免费的第二路
QROM 输出，减法是"量子 offset 的无条件 `isub`"（实测 w-1），因此电路里不出现
带符号中间量。若改写成 `e = 1-u; y' = y + y e/2` 并把 `e` 当成截断的补码乘数，
二次补码的符号扩展会被截断掉，结果错误（本轮实际踩到并修正）。

Goldschmidt（rsqrt 形式，`e_k = 1 - m y_k²`）：

```
y_{k+1} = y_k (1 + e_k/2) ,   e_{k+1} = (3/4) e_k^2 + (1/4) e_k^3
```

### 2.3 相位

```
phase = 2^-k * y ,  y 有 28 个小数位
theta = Y << (64 - 28 - k)        (Y = y*2^28，精确，无舍入)
```

y 的 bit 落在 `2^-1..2^-28`，右移 k∈[0,10] 后位置并集是 **1..38**，所以是 38 个相位位：
位置 1（2^-1 turn）是 Clifford 免费，位置 2（2^-2 turn）计 1 T，
位置 3..38 共 **36 个一般旋转**。这与验证器的
`num_z_pow(min_clifford_hierarchy_level=4)` / `num_t_like` 划分一致（已用 1 位
`z_pow(2^-j)` 逐 j 实测确认）。

要点：

- **1 次 Newton 不够**（2^-8 的种子一次只到 2^-16），2 次就足够且余量约 2 倍。
- 第二迭代的 `e` 至少要 24 bit：20 bit 时失败 2.74M 个 x。第一迭代可以只用 14 bit
  （Newton 把正确位数加倍：2^-8 → 2^-16 → 2^-32），这是设计 B 唯一的省钱空间。
- **Goldschmidt 的 `e` 必须一开始就是全精度。** 因为 `e` 的递推是
  `e' = (3/4)e² + (1/4)e³`，它假定 `e_k` 是精确值；若 `e_0` 有误差 δ，
  真实值变成 `ε_1 = ε_0² − δ`，误差线性传播。16 bit 的 `e_0` 失败 144 倍容差，
  30 bit 才通过。Goldschmidt 与 Newton 用同样 5 个乘法，没有成本优势。
- 第三次迭代没有任何改善（2 次与 3 次结果逐位相同）。

### 4.2 截断乘法：结构必须正确

`mul()` 用 `tmp` 作为宽度 `drop + w_out` 的累加器，每个部分积都加到 `tmp[k:]`（进位链
一直走到累加器顶端，窄操作数用 |0> 免费补齐），答案取 `tmp[drop:]`。因此

```
cost(w_u, W, ·) = Σ_{k<w_u} (2(W-k)+3) = w_u (2W - w_u + 4),   W = drop + w_out
```

与逐个实测完全一致。**`test_mul()` 用 5×4、drop=1、8 位输出的 512 种输入穷举仿真，
0 个不符**。

必须强调：`20261106_piecewise_cost/kernels.py` 里的 `multiplier()` 把
`acc[:width]` 加到只有 `|acc|` 宽的 `tmp[k:]`。本轮对 w_acc=w_u=4 做了 256 组穷举仿真：
它精确等于 `(A·U) mod 2^{w_acc}`（256/256 相符），而不是 `floor(A·U/2^{w_u})`
（只有 31/256 相符）。也就是说它给出乘积的**低位回绕**，产生不了 Newton 需要的高位。
它的门数仍可作为"w 位截断乘法"的下界，但按它计数会低估本文的乘法（本文数字更大）。

**下界论证**：第二迭代无法避免 `y1·u2/2`，其中 `y1` 必须是最终 28 位精度

所以乘数至少 11 位、累加器至少 29 位。**仅这一次乘法含反算就是 2,398C，
是全部 front+旋转预算 694.840824C 的 3.45 倍。** 而它只是五个乘法之一。

## 6. 为什么 Goldschmidt 也救不了

- 与 Newton 用**同样 5 个乘法**（`y0·u1/2`、`y0·u1/2` 的 e 递推 `e²`、`e³`、
  `y1·u2/2`），区别只是把一个 `m·y²` 换成两个低精度小乘法，省不到 10%。
- `e` 必须从第一次迭代就全精度（30 bit），因为 `e' = (3/4)e² + (1/4)e³` 假定 `e` 精确；
  16 bit 的 `e_0` 全域失败，最差 144 倍容差。
- 第三次迭代对结果没有任何改善。

| 家族 | 最省总 C | / 694.840824 | / 1,601.652 | Q |

本族比数字递推贵 4.2 倍。原因不是算法更差，而是**可逆乘法比可逆加法贵得多**：
一次受控 w 位加法是 2w+3，而数字递推每步只加一次且窗口随位数增长（28 位倒数递推
forward 只要 840C，含反算 1,680C），Newton 的一个 `m·y²` 就要 1,863C（含反算 3,726C）。
